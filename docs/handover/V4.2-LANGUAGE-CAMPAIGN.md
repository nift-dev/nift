# Nift v4.2.0 Language Campaign

## Frozen contract

v4.2 separates template grammar from `@fn` program grammar.

| Template | Function body |
|---|---|
| `@if(...) {...}` | `if(...) {...}` |
| `@for(...) {...}` | `for(...) {...}` |
| `@while(...) {...}` | `while(...) {...}` |
| `$[x := expr]` | `x := expr` |
| `$[x = expr]` | `x = expr` |
| `$[foo(...)]` | `foo(...)` |
| `break`, `continue` in loops | `break`, `continue` in loops |
| bare `return` in fragments | `return [expr]` |

Function statements accept newline, `;`, and block close as boundaries. `@fn` may return a value or no value; no value is `null`. Fragments remain template grammar and may only use bare value-less `return`. `break` and `continue` target the innermost `@for`/`@while` in the current callable boundary and cannot escape a function/fragment call.

`null` is a first-class scalar. Equality/inequality with null are valid; ordering with null is an error.

`copy` is reserved for shallow copying and `deepcopy` for recursive copying in the struct tranche after CP14.

## Struct tranche contract (CP15-CP27)

### CP15
Commit: this checkpoint commit.
Semantics changed: none; struct contract frozen before implementation.
Tests added: none.
Gates run: documentation consistency review.
Performance result: no runtime change.
Rejected alternatives: value semantics; implicit/dynamic fields; multiple constructors; inheritance/class hierarchy; implicit deep copies.
Next checkpoint: CP16 struct definitions.

Frozen contract:
- `@struct(name) { ... }` defines a fixed-shape user type and emits no output.
- fields are declared with `name := initializer`; an initializer is mandatory and fixes the field type.
- fields and methods are public by default; `private` may qualify either.
- methods use function-program grammar: `fn(name(args)) { ... }`; at most one constructor is allowed and is spelled `fn(struct_name(args)) { ... }`.
- instances have reference semantics. Assignment/passing/return aliases the same instance.
- `copy(x)` is an explicit shallow copy; `deepcopy(x)` recursively copies mutable aggregate state.
- fields/methods are implicitly visible inside methods; `this` explicitly denotes the receiver.
- no dynamic field addition/removal, inheritance, protected, overloads, destructors, generics, operator overloading or implicit JSON serialization in v4.2.
- methods may return a value, `return` without a value, or fall through; no-value results are `null`.
- constructor return values are forbidden.
