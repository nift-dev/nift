# Nift v4.4 — Root+Path B2 implementation handoff

## Starting point

This workspace was restored from the maintainer's pre-A/pre-B backup. The compact-Document/shared-Document experiments are therefore not present. The existing AST performance campaign is present.

## Chosen contract

Nested aggregate extraction is a **location reference**, not permanent object identity:

```f
a := [[1], [2]]
b := a[0]
```

`b` denotes the live location rooted at `a` with path `[0]`. Structural changes may therefore change what occupies that location. Missing paths fail safely and may become resolvable again if the location later exists.

JSONIC remains value-semantic and retains `vector<Document>` storage. No RuntimeValue/AggregateNode graph is introduced.

`copy(x)` is now intended to mean recursively independent copy. `deepcopy(x)` is retained as a compatibility spelling for this handoff; removal/deprecation should be decided only after a full docs/API compatibility audit.

## Important implementation caveat

`VariableBinding::sync()` currently re-resolves the path and creates a temporary aliasing `shared_ptr` to the resolved `Document`. This is safe only if **every use resyncs before dereferencing after any operation capable of relocating the parent**. Several major read paths were fixed here, but this must be audited comprehensively by DeepSeek.

A stronger final implementation may prefer a central transient `resolve_location()` use at every read/write boundary and avoid retaining even the temporary interior alias in `value`. Do not assume this handoff has proven every legacy/prepared path safe.

# DeepSeek implementation review (adversarial fix pass)

## Bugs found and fixed
1. **resolve_direct partial-root UAF**: reading `b[0]`/`b.x` after the parent
   array reallocated dereferenced the stale aliasing value; the root binding is
   now sync()ed before every partial-root read. (Original UAF reproducer, and
   even a single `a.push()` after `b := a[0]`, were heap-use-after-free.)
2. **Prepared for-loop element interior alias**: the loop binding was
   `shared_ptr<const Document>(col, &col->array[k])`; reading the element after
   in-body parent mutation dangled. Now a location reference (root slot + [k]).
3. **Legacy @for array element interior alias**: same class; now a location
   reference.
4. **Legacy @for map value binding interior alias**: `&entry.second`; now a
   location reference (string-key path).

All verified under ASan (original UAF reproducer, growth, prepared/legacy for,
map @for, missing-path safe error, path reappearance, root rebinding).

## Remaining interior-pointer sites (not yet converted)
- `json_bindings_` template-path aliases: `@for` tuple bindings
  (`json_bindings_[bindings[i]] = shared_ptr<const Document>(root, &element->array[i])`)
  and map @for key/value `json_bindings_` entries. These are used for template
  `$[...]` JSON-path resolution and are restored per iteration; they can dangle
  only if the @for body mutates the iterated collection. Lower reachability, but
  should be converted in the remaining campaign.
- `Parser::resolve_json_value` transient path walks (line ~960) return aliasing
  shared_ptrs; used only within the immediate resolution and discarded. Safe.

## Verified semantics
- location semantics: `b := a[0]; a.remove(0)` -> b resolves to new a[0];
  `a.prepend`/replacement observed; missing path errors safely; path reappears.
- root rebinding: `a = [[9]]` observed through b.
- function-arg/return location propagation: NOT yet implemented (CP22 pending);
  a location passed into a function loses location identity (no UAF).
