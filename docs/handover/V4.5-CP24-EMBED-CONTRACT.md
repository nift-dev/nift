# v4.5 CP24 — Supported embedding contract

The repository already contained the public C++ Engine/Context/Value surface,
C ABI, pkg-config staging, and Go/Python/Node/C# bindings before v4.5. CP24
promotes and freezes the native boundary rather than replacing it.

## Supported v4.5 native surface

- `nift::Engine` construction in standalone or project-aware mode.
- Typed Engine defaults and per-render `Context` overlays through `nift::Value`.
- Typed source rendering (`render`, `render_path`, `render_text`) and project
  tracked-page rendering.
- Atomic project snapshot `reload()` while renders continue on the prior
  snapshot.
- Host source-loader and environment-provider seams.
- CP25 adds complete script execution/evaluation to the same Engine.
- CP26 adds trusted host callable registration and host invocation of Nift
  callables.

The CLI remains a reduced target: `src/embed/*`, language bindings and the C ABI
are not linked into ordinary `make nift` except for shared core code that the CLI
already uses.

## Threading and lifetime

Separate Engines are isolated. Concurrent render calls on a configured Engine
are supported. Mutators remain forbidden concurrently with active operations
unless a method explicitly documents otherwise. Values returned from an Engine
own their data and remain valid independently of Parser temporary state.

## ABI/versioning

`NIFT_C_ABI_VERSION_MAJOR` is `1` for the promoted C boundary. Backward-compatible
additions increment the minor macro. A breaking C ABI change requires a major
increment. Existing exported function signatures are not silently repurposed.
The C++ API follows source compatibility rather than a stable binary ABI across
compiler/runtime combinations.
