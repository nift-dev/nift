# v4.5 CP20 — C ABI FFI contract

The v4.5 FFI is intentionally a **C ABI** boundary. It does not guess C++ ABI,
variadics, references, exceptions, member functions, or platform-specific
calling conventions.

## Script surface

```nift
lib := ffi_open(path)
value := ffi_call(lib, "symbol", "i64(i64,i64)", 2, 3)
ffi_close(lib)
```

`ffi_open` returns an opaque runtime-local library handle. `ffi_close` is
idempotence-rejecting: a second close is an error. Handles may not be used after
close and are closed automatically when their owning Parser is destroyed.

Signatures are `return_type(arg_type,...)`. Whitespace is ignored. Unsupported
or malformed signatures are hard errors before any native call occurs.

## v1 types

- `void`
- `bool`
- signed integers: `i8`, `i16`, `i32`, `i64`
- unsigned integers: `u8`, `u16`, `u32`, `u64`
- floating point: `f32`, `f64`
- `ptr`: opaque address represented as an FFI pointer handle, never a Nift number
- `cstr`: NUL-terminated UTF-8 string for call arguments; return strings are
  copied immediately into Nift-owned storage and may be null
- `buffer`: byte storage owned by a Nift FFI buffer handle (CP22)
- `struct{...}`: explicit field sequence with native C layout (CP22)

Scalar conversion is range checked. `null` is accepted only for nullable pointer
classes (`ptr`, `cstr`, `buffer`). Embedded NUL in `cstr` arguments is rejected.

## ABI and lifetime

- Native platform C calling convention only (`cdecl`/platform default).
- No variadics in v4.5.
- Library, pointer, buffer and callback handles are runtime-local opaque
  resources and are non-transferable through ordinary thread/async copying.
- Nift never frees a pointer returned by foreign code unless a package explicitly
  calls an exported deallocator through FFI.
- Returned C strings are copied before `ffi_call` returns.
- Struct size/alignment is computed from the declared fields and validated in
  CP22 fixtures.
- Foreign exceptions crossing the C boundary are undefined by the foreign
  library and unsupported; fixture callbacks never throw across C.

## Callback threading

Callbacks are introduced in CP22. v4.5 callbacks are valid only while their
owning runtime and callback handle are alive. Entry from a foreign thread is
rejected unless it can be marshalled onto an owning Nift execution context;
there is no unsynchronised concurrent Parser entry.

## Portability

Dynamic loading uses `dlopen`/`dlsym` on ELF/macOS and
`LoadLibraryW`/`GetProcAddress` on Windows. Tests use a deterministic local C
fixture; they never download libraries.
