# v4.6 Batch 3 explicit module/package resource paths

## Checkpoint

This checkpoint builds on the committed CP7/CP8 import ownership model without
rewriting it. `ModuleEnv::source_path`, `import_base`, and `package_root` remain
the durable authority, including the graph cloning already used by thread and
future workers. The new path APIs consume that ownership; they do not infer a
new owner from the caller CWD.

Source provenance is explicit, not inferred from path spelling. Parse execution
frames, named callables, struct methods, lambdas, and module environments carry
`FileBacked` or `InMemory`; worker graph clones preserve it. A logical in-memory
name can therefore equal a real source path without changing the real source's
authority. Workers retain their existing standalone behavior for ordinary
filesystem APIs, while a separately copied resource-path authority preserves the
originating project/embed root or `NIFT_FS_ROOT` for these two APIs. That
authority is canonicalized once at parser construction, after CLI options are
applied, and workers receive the exact snapshot. It is never re-anchored after
`cd()`.

`module_path()` returns the absolute normalized directory containing the current
file-backed source module. Its optional non-empty string argument is resolved
from that directory. `package_path()` returns the absolute normalized root of
the package owning the current module and resolves its optional argument from
that root. Zero or one argument is accepted. Empty strings are deliberately
errors so the zero-argument form remains the only spelling for the base itself.

Rooted, absolute, Windows drive-qualified, UNC, and backslash-rooted arguments
are rejected before joining. Every package-owned result, including
`module_path(relative)`, passes lexical and `weakly_canonical` containment
against the package root. Existing symlink/reparse prefixes therefore cannot
escape, while a non-existent leaf or contained missing parent remains valid.
Project/embed execution retains project-root authority and standalone
`NIFT_FS_ROOT` retains its configured authority. Ordinary standalone local
modules retain their prior unrestricted filesystem authority.

There is no CWD fallback. Direct eval, `-e`, REPL, stdin, and in-memory embed
sources, including text sources with logical diagnostic names, report that no
file-backed source exists. `package_path` outside package ownership reports a
separate controlled error. The APIs return strings only and do not probe the
target for existence or alter any existing filesystem API.

Package module environments retain immutable provenance captured under the
initial package read lock: project/package identity and the lock entry's
`source`, `requested`, and exact commit or `local`. Nested package modules and
worker clones copy that provenance without retaining a lock. Every delayed
package-relative import and `module_path`/`package_path` resolution acquires a
short read lock, compares the current lock and installed identity with the
frozen provenance, and rejects stale remote ownership in a controlled way. The
lock is released before child code executes or a path string returns, so a live
callable can synchronously run a child package command without deadlocking.
Unchanged local provenance deliberately retains live-source behavior. Failed
imports still erase their uncommitted module graph. Because these APIs return
path strings rather than handles, replacement after lock release and before a
later I/O operation is an inherent path-string TOCTOU boundary.

## Ownership

Top-level package initialization uses the loading module. Later exported named
functions, methods, lambdas, callback values, nested/re-exported callables, and
their worker snapshots use the active defining module already established by
CP8. Local imported modules use the same source ownership with an empty package
root. Prepared AST calls and compatibility evaluation route through one shared
resolver, preventing semantic drift between execution paths.

## Verification

`tests/v46_resource_paths.py` covers ordinary and nested file sources, package
top-level values and delayed functions/methods/lambdas/callbacks, CWD changes,
workers, traversal, Unix and Windows-shaped rooted arguments, empty/type/arity
errors, symlink escape, missing contained targets, local authority,
`NIFT_FS_ROOT`, relative-root stability across `cd()`, source-less CLI modes,
completion, and unchanged CWD-relative `open` behavior.

`tests/v46_resource_paths_embed.cpp` covers execute/evaluate/in-memory errors,
logical-name collision non-authority, path-backed rendering, imported module
ownership, in-memory thread/future errors, and copied project-root confinement
for local-module thread/future workers. Package transaction coverage verifies
unchanged provenance, live local sources, synchronous child updates without
deadlock, and controlled stale ownership after direct and worker-delayed path or
relative-import replacement; the persistent parser unit verifies failed-import
rollback and immediate scoped-lock release.
`test-v46-resource-paths` is the focused gate;
`test-v46-resource-paths-sanitize` runs the CLI/package/worker and embed cases
under ASan/UBSan/LSan. The package, embed, language, import, and concurrency
walls retain their existing roles and are rerun for checkpoint reconciliation.
