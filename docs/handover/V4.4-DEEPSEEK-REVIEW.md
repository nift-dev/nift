## Independent review/repair pass (2026-09-19)

An independent adversarial review + dogfood + repair pass covered CP1-CP40
(see the review report for the full record). Everything below reflects the
post-repair state at commit HEAD of `main` unless stated otherwise.

### Regressions found and fixed (all committed with regressions)

- **`copy(value)` value-copy regression (CP5).** Generalizing copy/cp/move/mv
  to filesystem operations intercepted the v4.3 single-argument value copy of
  collections/structs, breaking existing templates/scripts and the v42/v43
  source + independent regression walls (4 independent modules failed). The
  filesystem branch now only claims copy with 2+ arguments.
- **`pick()` ordering regression (CP8).** Structured-key wildcards changed
  pick result ordering from the requested pattern order to object order. pick
  now walks requested patterns first, restoring requested-order semantics while
  retaining wildcard matching.
- **`@import` exported-callable closure (CP30/CP34).** Exported `@fn` callables
  could not reference the module's private callables or top-level bindings, so
  the sqlite package (and any package with internal helper functions) failed
  with "undefined callable". Exported callables now carry a shared module
  environment (callables + top-level bindings) active while their bodies run,
  preserving import isolation.
- **`--no-process` (CP27).** The documented CLI flag was rejected by `nift
  run`/`nift sh`; only the NIFT_NO_PROCESS environment variable worked. The
  flag is now parsed, and the structured `cmd(...).run()` pipeline path (which
  bypassed the restriction entirely) now denies process execution too.
- **SQLite package (CP35-CP37).** `sqlite_literal` checked `type() ==
  "number"` but `type()` returns "int"/"float", so numeric parameters never
  bound; `inject(variable)` only accepted a quoted literal (fixed in Nift
  core); the query temp file had a fixed name (now `mktemp`); transactions
  used a single BEGIN/COMMIT batch that committed partial work on error (now
  `sqlite3 -bail`, which rolls back atomically); empty result sets produced an
  empty temp file (now returned as `[]`).
- **Shell state (CP14/CP15).** `x = 7` and compound assignments were routed to
  command land and silently attempted to exec a program named `x`; lines whose
  second token is a standalone assignment operator now route to the Nift
  statement engine. The tokenizer split an adjacent fd-redirect such as
  `2>err.txt` into a literal `2` argument plus a stdout redirect; `2>`,
  `2>>`, `2>&1` now tokenize as fd-redirects.
- **inject() path evaluation.** `inject` only accepted a quoted literal path;
  non-literal arguments are now evaluated as string expressions, and the
  standalone-path containment check is relaxed to match the CP10
  filesystem-authority model.
- **Parser mutation-candidate heuristic.** `=`/`:=` inside quoted strings
  (e.g. SQL `WHERE x = ?`) were treated as assignments, breaking postfix
  composition on calls such as `fn("a = b").member`. Assignment operators now
  only count at bracket/paren/quote depth zero.
- **Test wiring.** `v44_shell_glob`, `v44_cp21_history`, `v44_cp22_completion`,
  `v44_cp27_restricted`, `package_refs`, `package_sqlite_dogfood` were not
  wired into the Makefile. They now run under `make test-v44` (and the core
  shell/language/restriction targets join `make test`). Fixed the
  `$OLDPWD/$NIFT` absolute-path bug in three tests, the missing `sh`
  subcommand in the shell-glob test, and its printf format.
- **Highlighter (CP28).** The website grammar treated `//` and `#` as Nift
  comments, but Nift comments are `@//` and `@/* ... */`; it now matches the
  real forms. `check_syntax_highlight.py` was expanded from the @path family
  to the full modern grammar with rule-scoped false-positive checks.

### Verified sound (no change)

- Variadics/spread: user functions, lambdas, fixed+variadic, recursion,
  closures, diagnostics, empty/heterogeneous args, non-array spread rejection.
- Filesystem globs (`*`, `?`, `**`), deterministic ordering, dotfile rules,
  no-match semantics per the CP6 contract, object-key wildcard matching kept
  separate from filesystem globbing.
- map-to-markup block lambdas (rendered vs non-rendered, nested control flow,
  empty arrays, composition).
- Process core: direct fork/execvp (no shell), real OS pipes for intermediate
  pipeline stages, capture via temp files, exit codes/stdout/stderr, PATH
  lookup, env inheritance, large output, `-bail` behavior.
- Command resolution precedence (Nift builtins > PATH), `which`, native
  aliases (cp/mv/rm/mkdir).
- Package manager: local paths, file:// Git sources, `latest`/`latest-tag`/
  explicit refs, lockfile reproducibility (install stays locked, update
  advances floating refs), remove/install/update.
- Build-hook configuration contract (project + per-file): parsing, validation,
  malformed-name/value rejection. Actual hook lifecycle execution remains
  unfinished and is NOT claimed complete.
- `niftrc`, history persistence, `nift complete` deterministic engine.
- Performance: full 10k build 0.118s / no-op 0.078s / shared-template 0.137s,
  within or better than the recorded 4.2/4.3-era baselines.
- Valgrind (Linux, 3.26.0-equivalent): process/pipeline/glob/variadic loop and
  the full SQLite package matrix both report 0 errors, 0 bytes in use at exit.

### Known unfinished (do not start without the completion pass)

  completion (`nift complete` covers builtins + PATH + files only).
- True native structured build/project bindings (CP23/CP24): Automation.h
  freezes the boundary; ProjectInfo/CLI extraction is not finished.
- Actual project-wide and per-file build-hook lifecycle execution, ordering,
  failure propagation, incremental semantics (CP25/CP26 config contract only).
- `nift run`/build restriction parity and filesystem-root restriction beyond
  `--no-process` (CP27).
- Windows process/pipeline/shell/package parity (Process.cpp returns "backend
  not yet available on this Windows build").
- Visual syntax-highlighting certification of shell prompt/cwd styling and the green `nift sh` prompt (the ANSI codes are verified via the PTY tests; browser/rendered verification is CI-pending).
- The official `nift-packages` registry repositories are placeholders (no
  manifest at the `sqlite` remote root), so `nift add sqlite` cannot install
  from the registry until they are populated; local/Git-source installs work.
- Complete sanitizer/ASan/UBSan campaign and cross-platform CI; performance
  comparison was sanity-checked only.
- The v1 sqlite3-CLI backend cannot guarantee temp-file uniqueness across
  independent processes in one directory (mktemp handles single-process
  concurrency); `mktemp`/`sqlite3` are additional runtime dependencies.
- `$[...]` interpolation inside command-style shell arguments is not
  implemented (documented in the plan, not yet claimed in docs).
- `;` command separator, background jobs, heredocs, subshells are not
  implemented (`&` fails explicitly).

## CP31-CP40 completion/review notes

CP31-CP34 now provide the first Git-native package-manager implementation: local packages, arbitrary Git/GitHub sources, the `nift-packages/<name>` short-name registry convention, `add/remove/install/update`, exact-commit locks, `latest`/`latest-tag`/explicit refs, and package-name `@import`. DeepSeek should attack rollback/interruption behavior, dependency conflicts/transitives, Windows symlink/local-package behavior, semantic-version edge cases, offline installs, malicious manifests/path traversal and completion/provenance integration.

CP35-CP37 created the sibling `sqlite` package with `manifest.json`, backend-neutral API and an initial `sqlite3` CLI backend. After this review the real database matrix is green (DDL/DML/query/null/quoting/transactions/errors/large results), SQL parameter substitution uses doubled-quote escaping, query output uses `mktemp` temp files with cleanup, and transactions use `sqlite3 -bail` for atomic rollback. Remaining: cross-process temp uniqueness, `mktemp`/`sqlite3` dependency footprint, Windows.

CP38 adds local-package dogfood. CP39 deliberately leaves native HTTP/fetch out pending real package evidence. CP40 deliberately leaves full job control/heredocs/subshells/command-specific completion out pending dogfood; `&` now fails explicitly rather than silently running synchronously.

Still outstanding from CP21-CP30 remains outstanding unless separately fixed: interactive TAB terminal integration, true native structured build/project bindings, actual project/file hook lifecycle execution, full restriction parity, visual highlighter certification, Windows process/shell/package parity, and the complete sanitizer/ASan/UBSan/LSan/Valgrind + performance + full independent regression campaign.
