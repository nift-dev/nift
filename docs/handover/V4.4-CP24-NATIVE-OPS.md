# CP24 native project/build operations

Target script API: `build()`, `build_all()`, `build_names(...)`, `track(...)`, `untrack(...)`, and structured project/list queries. They must call the same ProjectInfo engine used by the CLI and return `NiftOperationResult`-equivalent values; they must never recursively spawn `nift`.

Current blocker for follow-up review: ProjectInfo is still CLI-owned enough that exposing it directly through Parser would create a circular/duplicated boundary. CP23 freezes the result/request contract; DeepSeek should complete the extraction before release rather than accepting a subprocess shim.
