## Approved Semantic Contract

The design document above is normative. Its central rules are:

- Catchability is an explicit diagnostic disposition, never a message-prefix,
  category, platform-error, or exit-status inference. `try` catches only
  `Recoverable`; `Fatal` always reaches the existing top-level boundary.
- A genuine Error is an interpreter value with immutable message, code,
  category, trusted origin, and Error/null cause. Public construction accepts
  only validated `user.*` codes; built-in namespaces cannot be forged.
- The first valid throw origin wins. Propagation adds private typed frames and
  never rewrites the origin. Rethrow preserves the same observable Error.
- Language errors move through explicit outcomes, not C++ exceptions or a final
  parser-global throw-control flag. C++ catches remain containment boundaries
  for unexpected native exceptions only.
- Existing structured-result APIs remain results. A process nonzero exit,
  `{ok:false}` package result, `exists() == false`, host result, and analogous
  domain outcome do not automatically throw.
- Security, authority, policy, syntax, programmer misuse, invalid handles,
  arithmetic failures, malformed metadata, and interpreter invariants remain
  fatal even when continued execution might otherwise be convenient.

## Delivered Surface

- Internal structured diagnostics carry disposition, code, immutable origin,
  and typed propagation frames while preserving existing public result layouts.
- `RuntimeType::Error` is appended as ordinal 9. Error values are immutable,
  validate custom `user.*` codes and bounded cause chains, retain their first
  trusted throw origin, and support deterministic equality and fingerprints.
- Contextual `throw expr` and `try { ... } catch(name) { ... }` are implemented
  without reserving identifiers in declarations, call position, members, or
  compound assignments. Only Error values can be thrown. Fatal failures bypass
  catch.
- Prepared and legacy execution propagate recoverable outcomes through
  callables, methods, loops, imports, templates, scripts, REPL evaluation,
  futures, and threads. Repeated `await` and `join` replay the same Error.
- Failed worker-owning imports always become fatal
  `internal.import_lifecycle`. Their complete parser-owned graph remains alive
  until top-level worker finalization, after which deferred cleanup and
  parser-local identity rollback run.
- Error values are recursively rejected from successful public transport and
  rendering boundaries, including arrays, objects, parser collections and
  structs, interpolation, joins, files, streams, CLI eval, C++ Engine/Context,
  host callables, public Value conversion, C ABI, and maintained bindings.

## Compatibility Pins

- `error`, `throw`, `try`, and `catch` remain legal identifiers, members,
  callable names, host callable names, and module names. Only exact statement
  forms are contextual. `throw(value)` remains a call while `throw value` is the
  statement; compound assignment such as `throw += 1` remains valid.
- Direct template `@try`/`@catch` is not added. Script grammar inside supported
  script/function/method/lambda bodies owns the new control forms.
- `Unsupported` means only prepared-to-legacy capability fallback. It is not a
  language error, and a real prepared failure must never fall back and execute
  an operation twice.
- Existing RuntimeType ordinals are unchanged; Error is appended as ordinal 9.
  Ordinary objects with Error-shaped fields never gain Error privileges.
- Error `stringify`/`prettify` is a stable diagnostic representation, but strict
  JSON rejects Error and cannot construct it. Implicit rendering rejects Error;
  code must deliberately render fields such as `err.message`.
- Existing diagnostic text and source projection remain pinned for characterized
  legacy failures. `import:`, `future:`, and `thread:` are compatibility-frame
  projections, not semantic code selection.
- Return location root/path identity, loop ownership of break/continue, callable
  ownership of return, output captured before failure, and persistent REPL state
  must not regress during later producer conversion.

## Recoverable And Fatal Taxonomy

The exhaustive automatic v1 recoverable set is: explicit Error throw; valid
filesystem operations failing from external state; backend stream failures on a
valid live stream; malformed runtime JSON; rejection by a valid schema; valid
FFI load/symbol lookup failures; missing or unreadable import sources after safe
rollback; and recoverable worker completion observed by `await` or `join`.

Fatal examples include syntax/translation/name errors; bad arity, type, mode,
index, mutation or control placement; arithmetic/domain/depth failures;
privacy/export and authority/policy failures; malformed schema/package/lock
metadata; forged, stale, closed or wrongly owned resources; unsafe import
lifetime; host/provider and native exceptions; interpreter invariants; native
faults; and FFI signature/argument/handle misuse. The exact code families and
branch eligibility are in the CP2 registry and must be selected at producers.

## Public ABI Restrictions

- No C++ public-result layout or C ABI redesign is part of v1. Existing
  `ScriptResult`, `RenderResult`, C ABI mechanical status, diagnostic projection,
  and maintained binding contracts remain intact.
- Semantic language failure remains a result and must not become
  `NIFT_ERROR_INTERNAL`. C ABI script results still expose only message; render
  results expose message/source/line/column.
- Error code, category, cause, and structured frames are internal-only in v1.
  No public accessors or ABI-version change are authorized by Batch 4A.
- A successful graph containing Error at any depth must be rejected before it
  crosses public Value, Engine/Context, host callable, C ABI, JSON, or binding
  transport. Do not expose Error as a successful public value.

## Worker And Import Lifetime

- `WorkerCompletion` stores `Pending | Value | Recoverable(Error) |
  Fatal(Diagnostic)`. Repeated observation must replay the same immutable
  completion, and observer frames must not replace the defining origin.
- Any failed import that created a future or thread is deterministically fatal
  `internal.import_lifecycle`, regardless of worker completion timing or the
  original failure disposition. Language catch must not intercept it.
- Its full parser-owned graph, tracked source, module environment, host and
  worker references remain alive until existing top-level drain/join completes.
  Cleanup and parser-local identity rollback run only afterward. Never detach a
  worker or rewind process-global monotonic IDs.
- Nonterminating workers may retain the existing blocking teardown behavior.
  Cancellation and nonblocking lifetime redesign are outside v1.

## CP4 Entry Conditions

CP4 may convert only the filesystem, FileValue, stream, runtime JSON, and schema
validation operational failures explicitly approved in the registry. Keep
argument, type, mode, authority, policy, resource lifecycle, malformed schema,
and implementation failures fatal.

Before changing a producer:

1. Identify its code and disposition directly at the branch; never infer either
   from message text or prefixes.
2. Preserve retry and rollback behavior, especially failed FileValue saves and
   stream state.
3. Preserve the defining diagnostic origin and append frames at propagation
   boundaries rather than replacing it.
4. Add prepared/legacy parity and public-boundary tests for every converted
   family.
5. Re-run `make test-v46-b4-cp3` as the immutable Batch 4A regression baseline.

Do not broaden catchability to process results, host failures, package commands,
network/database APIs, native tools, syntax/type/arity/privacy/arithmetic/policy
failures, or any other CP5+ or explicitly deferred surface.
