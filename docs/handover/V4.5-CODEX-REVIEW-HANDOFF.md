## Review mandate

Review architecture and implementation, not just green tests. In particular:

1. Unified CLI dispatch: direct paths, zero-arg REPL, `-e`/`-c`/`-i`, stdin source, `cmd`/`args`, removed `run`/`sh`, ambiguity/error handling and shebangs.
2. `os()` / `arch()` / `target()` / environment isolation, including embedding host ownership and build-target propagation.
3. POSIX job control: process groups, TTY ownership, signals, stopped/running/done transitions, pipelines, background reaping, `fg`/`bg`/`jobs`/`wait`, shell shutdown and platform fallbacks.
4. Native concurrency: transfer/copy rules, callable capture, thread teardown, replayable join/await, shared mutex state, `atomic<int>` / `atomic<bool>` semantics and cross-worker transfer, worker-pool starvation avoidance, nested async, error propagation and runtime destruction.
5. FFI: signature parser, dynamic-library lifetime, scalar conversions/range checks, buffers/struct layout, pointer ownership, callbacks/reentrancy and unsupported ABI rejection. Look specifically for use-after-close/use-after-free and cross-thread callback hazards.
6. Embedding: Engine script state, host seams, execute/evaluate, C ABI 1.1 compatibility, native host callables, multiple runtime isolation, same-runtime serialization and teardown while async/FFI objects exist.
7. Maintained bindings and staged artifacts: Go/Python/Node/C#, C/C++ consumer API, headers/pkg-config/shared/static linkage and versioning.
8. Cross-platform compilation and behavior on Linux/macOS/Windows; do not treat Linux code review as Windows certification.
9. Performance: ensure unused concurrency/FFI/embedding machinery does not impose material ordinary CLI/build startup costs.

Any bug found must get the smallest practical reproducer and a permanent source/black-box regression where the behavior is externally observable.

## Known local-environment limitations, not waived gates

- This tool environment kills/terminates the enormous optimized or sanitizer-instrumented `Parser.cpp` compile when a single command exceeds its execution/resource window. CP34 therefore does not claim final clean optimized GCC/Clang walls.
- The full serial regression runner also exceeds the local command window. Focused v4.5 modules are green. The unreadable-file contract must run as an unprivileged user; this container's privileged user can still read chmod-000 fixtures.
- `dotnet` is unavailable locally, so C# was source-updated but not runtime-certified here.
- Local Go is 1.23 while the maintained binding module requests Go 1.26. A temporary untracked compatibility copy passed `go test ./...`; the real declared toolchain remains a CI gate.
- Valgrind is not installed.
- macOS and Windows require hosted/native runners.

These limitations are reasons to run the gates elsewhere, **not** reasons to delete tests, downgrade flags, loosen contracts or modify repository history.

## Repair discipline

- Begin every repair with `git status --short --branch` in the affected repository.
- Never use `git reset --hard`, repository reinitialization, force checkout of the workspace root, history squashing, or bulk replacement from another checkout.
- Preserve nested `.git` repositories and symlinks.
- Keep fixes narrow; inspect `git diff --check` and staged diff before every commit.
- Commit after each bounded repair and rerun the focused reproducer immediately.
- After convergence, rerun the complete walls and `git fsck --full` for every repository.
- Do not push/tag/publish until the maintainer explicitly asks.
