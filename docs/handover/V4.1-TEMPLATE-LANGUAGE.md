# Nift v4.1 template-language campaign

Status: active

This file is the authoritative handover for the v4.1 template-language campaign. Update it at every checkpoint. The normal Nift model remains deliberately small (`@input`, `@content`, `@path`); these features are optional advanced templating.

## Frozen language contract

- `$[x := expr]`: declare a mutable binding in the current scope. `:=` is right-associative and may shadow an outer binding.
- `$[x = expr]`: assign the nearest visible existing mutable binding. `=` is right-associative and never declares.
- Top-level declaration/assignment interpolation emits nothing, although assignment/declaration expressions evaluate to the assigned value internally for chaining.
- Types are inferred at declaration and stable for the lifetime of that binding; incompatible reassignment is an error.
- `$[const x := expr]`: shallow-const binding (no rebinding).
- `$[immut x := expr]`: deep read-only binding/view; no global freeze of mutable aliases.
- Child scopes inherit visible bindings and may mutate existing outer mutable bindings. New declarations are local. `@if`, `@for`, `@input`, `inject()`, `@fn` calls and `@fragment` calls use this model.
- No `global` escape in v4.1.
- `@:=(name){ expression }`: generic multiline declaration; outer braces are directive framing, not part of the expression.
- `inject(path)`: expression-source injection. Parse/evaluate the file as Nift source at the expression position; no extension-based typing. It creates a child scope and a tracked dependency.
- `validate(schema, value)`: validate and return `value` unchanged on success.
- `@input` remains normal template/output inclusion.
- Loop variables are local. Iteration is live over the underlying collection; rebinding the source variable does not retarget an active iterator.
- `@fn(name(args)){...}` returns an ordinary value; `@fragment(name(args)){...}` returns rendered template content.
- Both are invoked only as `$[name(args)]`, preserving unknown `@...` passthrough such as CSS `@media`.
- Old `@json` forms are retained until declaration/inject/validate parity is proven, then reconciled/deprecated.
- Queues, stacks, maps, priority queues, structs and classes are out of scope for v4.1.

## Acceptance rules

Every checkpoint is a separate commit. Existing-template behavior, dependency tracking and passthrough are regression gates. Run relevant focused tests plus the full suite at architectural boundaries. Measure performance during development; do not accept material regressions in ordinary templates that do not use the new language.

### CP25 — independent certification review (external campaign)
- Commit: this checkpoint commit (`Fix v4.1 expression/callable defects found by independent certification` and follow-ups).
- Semantics changed: no frozen-contract changes; genuine defects found by an independent review/adversarial campaign were repaired, and one historical JSON integration regression and one stale minifier expectation were reconciled.
- Defects found and fixed (each covered by `tests/v41_certification_adversarial.sh`, mirrored as `nift-regression-suite/contract/v41_certification_adversarial.sh`):
  1. `last_expression_mutation_` leaked out of nested evaluations, so a function that declared a local or mutated an outer binding, a fragment with a body declaration, or `inject()` nested inside a larger expression silently suppressed the enclosing `$[...]` output. Now depth-scoped with save/restore around callable bodies and `inject()`.
  2. `@fn` always took the last `@return(expr)` via `rfind`, ignoring `@return` inside taken `@if` branches. `@return` is now a directive inside function bodies and unwinds the current parse level through nested constructs.
  3. `@for` loop variables did not shadow an outer v4.1 binding of the same name; loop bindings are now declared in the per-iteration child lexical scope.
  4. Undefined callables such as `$[not_a_function(...)]` rendered literally; unknown `name(...)` expressions now fail with "undefined callable".
  5. Structured v4.1 bindings only supported dot member paths; `.member` and `[index]` segments now walk using the legacy path syntax (`$[x[1]]`, `$[o.a.b[0]]`).
  6. `parse_parameters` stripped every quote character, breaking structured-literal arguments to callables/`validate()`; only exactly-quoted-string parameters are stripped now, with quotes inside `{…}/[…]` preserved and legacy in-string escape rules retained for quoted parameters.
  7. Callable recursion was unbounded; a callable-call depth bound (64, matching the parse-depth guard) now fails cleanly and is verified to prevent ASan stack overflow.
- Historical regressions reconciled:
  1. Jsonic++ v1.0.0 defaults to preserving duplicate object keys; Nift historically rejected them in every parsed document. All Nift parse sites now use `nift_json::parse` (DuplicateKeyPolicy::Reject), restoring v4.0.13 behavior for config, tracked state, `@json` data, schemas, inline and expression literals.
  2. Minify++ v1.1.3 elides trailing JS semicolons after delimiters (`const q = 1 ;` -> `const q = 1`); the integration tests asserted pre-v1.1.3 output and were reconciled to the certified v1.1.3 release.
- Gates run: full Nift `make test` PASS; `test-all` (embed + bindings + build boundary) PASS; all engine/concurrency/TSAN walls PASS; independent regression suite 32/32 modules PASS (historical ruthless contract + all contract modules, including the new `v41_duplicate_key_smoke.sh`); ASan/UBSan adversarial + parser fuzz (1200+ cases across seeds) clean; Valgrind clean on the v4.1 adversarial wall and checkpoint gates; scenario 11 zero-mutation/recovery/ownership PASS; website and benchmark-site dogfood builds byte-identical to v4.0.13 with no-op/modified rebuild correctness; v4.1-vs-v4.0.13 performance shows no material regression in existing-template workloads (plain ≈ 1.005×; new-feature workloads reported separately as diagnostics).
- Dependency verification: the vendored Jsonic++ tree is byte-identical to tag `v1.0.0` (`88e4736`) and the vendored Minify++ tree is byte-identical to tag `v1.1.3` (`43288d1`). The dependency sync check compares against the sibling release tag for the declared vendored version (not sibling HEAD), so it is green even though the sibling checkouts are on post-release development heads (1.0.1-dev / 1.1.4-dev). The checker self-test (`tests/check_nift_sync_test.sh`, wired into `memory-safety-checkpoint-6-sync`) covers HEAD-at-tag, HEAD-ahead, dirty tree, payload mismatch, missing tag, newer sibling release and checker desync.
- Performance result: binding replacement remains O(1) shared-handle replacement; structured Document materialisation may still copy and is documented accurately.
- Rejected alternatives: weakening any regression test instead of fixing the implementation; treating the intended Minify++ v1.1.3 JS output as a defect; lowering the duplicate-key strictness below the historical contract.

Independently certified during CP25: full native wall, independent regression suite, sanitizer/memory-safety/Valgrind walls, fuzz sweep, scenario 11, website dogfooding, and the v4.1-vs-v4.0.13 performance comparison.

Intentionally unsupported: queues, stacks, maps, priority queues, structs and classes (out of scope for v4.1); member/container-level mutation of structured bindings (no member-assignment syntax exists in v4.1). `const` prevents rebinding; `immut` establishes a recursively read-only binding/view contract. Because v4.1 does not yet expose member/container mutation syntax, much of the `immut`/`const` distinction is currently latent rather than independently observable — an `immut` view does not globally freeze storage reachable through a separate mutable binding (verified by alias tests), and when member/container mutation arrives later, `immut` already determines what must be rejected.
