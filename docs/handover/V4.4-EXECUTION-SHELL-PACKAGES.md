# Nift v4.4.0 — execution, shell and packages

Status: **planned**. Start only after the v4.3.0 line is deliberately closed and the maintainer authorizes v4.4 work.

v4.4 turns the v4.3 language into a coherent execution environment: variadics, spread, wildcards, a real cross-platform shell, process interoperability, native build/project scripting, lifecycle hooks, and a Git-native Nift package ecosystem. The first package is `nift-packages/sqlite`.

## Campaign rules

- Expression calls stay `fn(a, b)`. Script/shell command calls may use `fn a b`; unquoted command arguments are literal tokens so `rm *.o` and `cp assets/**/* public/assets/` need no quotes. `$[...]` bridges command arguments back to evaluated Nift values.
- Variadics are general: user functions, lambdas and eligible native functions use trailing `...args` as an ordinary heterogeneous array; spread expands arrays into arguments.
- Define wildcard semantics once. Reuse them for `ls`, `cp`, `mv`, `rm` and external-command glob expansion. Structured-data wildcards are a separate contract.
- `cp`, `mv`, `rm`, `mkdir` are Nift-native aliases, not platform utilities.
- External execution uses direct executable + argv spawning, not `system()`/implicit Bash. Explicit Bash remains allowed.
- Command-style process syntax should match familiar Bash syntax where practical (`|`, redirections, `&&`, `||`, `&`, quoting/escaping, env assignment), while normal Nift syntax uses structured `run()`/`cmd()` APIs over the same process engine.
- Standalone scripting follows normal OS-user authority by default; restrictions are opt-in.
- Packages are Nift `.f` code. Do not reintroduce Lua/LuaJIT for packages.
- Every public behavior checkpoint accounts for source tests, independent regression coverage, website docs/examples and handover/decision updates.
- Preserve performance/RSS; guard against hidden O(n²) glob, PATH, package-graph and hook work.

```text
foo(a, b)                  # explicit Nift callable
run("foo", "a", "b")      # explicit external process
foo a b                    # command-style resolution in script/shell land
```

## Phase A — language and argument foundation

## Phase B — execution and filesystem authority

### CP10 — standalone filesystem authority
- [ ] Separate build path invariants from `nift run`/`nift sh` authority.
- [ ] Allow normal absolute/parent/home paths subject to OS permissions.
- [ ] Preserve build dependency/output safety; prove distinction cross-platform.

### CP11 — process core
- [ ] Implement direct executable + argv spawning (`posix_spawnp()` candidate on Unix; `CreateProcessW()` on Windows).
- [ ] Inherit cwd/environment/auth context so existing `git`, `gh`, SSH-agent/cloud auth works.
- [ ] Return exit code/stdout/stderr; handle not-found/non-zero/termination.
- [ ] Do not make `system()` the primary implementation.

### CP12 — `run`
- [ ] Expose `run()` broadly unless restricted by invocation capability.
- [ ] Support `run("git", "status", "--short")` and spread arrays.
- [ ] Separate captured programmatic output from interactive streaming.
- [ ] Permit explicit `run("bash", "-c", "...")`; test with controlled helper executables.

### CP13 — structured command/pipeline API
- [ ] Keep `run(...)` as the convenient synchronous single-process API returning structured exit/stdout/stderr results.
- [ ] Add a first-class command builder, provisionally `cmd(...)`, that does not execute until `.run()`/`.start()`.
- [ ] Support real streaming OS pipelines in normal syntax, e.g. `cmd("git", "log").pipe(cmd("grep", "fix")).run()`, without buffering whole intermediate outputs in Nift.
- [ ] Add structured stdin/stdout/stderr routing to files/streams, including truncate vs append, cwd, environment overrides and timeout where justified.
- [ ] Preserve per-stage process status/error information sufficiently for robust scripting and agents.
- [ ] Design eventual `.start()`/process-object semantics so background execution/job control can build on the same core rather than a second process implementation.

### CP14 — persistent shell state
- [ ] `nift sh` owns cwd, typed Nift variables and string OS environment variables.
- [ ] Child processes inherit cwd/environment.
- [ ] Rationalize getenv/set/export/unset with existing `@getenv`.
- [ ] Prove native state changes persist while child changes cannot mutate parent state.

## Phase C — command-style shell

### CP15 — command grammar
- [ ] Add command-style calls only in standalone script/shell land.
- [ ] Unquoted args are literal tokens/paths (`rm *.o`); quotes handle whitespace; `$[...]` injects evaluated values.
- [ ] Use Bash-compatible command-style quoting/escaping/token behavior wherever practical so existing shell knowledge transfers directly.
- [ ] Keep normal expression syntax unambiguous and separate from command-land parsing.
- [ ] Test assignments/operators/comments/calls/path punctuation ambiguities.

### CP16 — Bash-compatible pipelines and redirection
- [ ] Support `cmd1 | cmd2` as a real streaming OS pipeline in command land.
- [ ] Support `<`, `>`, `>>`, `2>`, and `2>&1` with Bash-compatible meanings where practical.
- [ ] Support `&&` and `||` conditional command chaining and preserve meaningful exit-status behavior.
- [ ] Support `&` for background execution once the process-object/job substrate is safe enough; do not fake backgrounding by detaching unmanaged children.
- [ ] Support leading environment assignment such as `FOO=bar command` without mutating the persistent shell environment.
- [ ] Ensure quoting suppresses glob expansion/redirection/operator interpretation as users and agents expect from Bash.
- [ ] Parse command syntax into the same internal command/pipeline representation used by `cmd()`; do not maintain a second execution engine.
- [ ] Add black-box parity fixtures for representative Bash-style pipelines/redirections on Linux/macOS and equivalent Nift behavior on Windows.

### CP17 — native aliases
- [ ] Add `cp` -> `copy`, `mv` -> `move`, `rm` -> `remove`, `mkdir` -> `make_dir`.
- [ ] Preserve pleasant `ls`, `cd`, `pwd`, `cat`, `touch`, `exists` forms.
- [ ] Use Nift implementations/wildcards everywhere.

### CP18 — command resolution/PATH fallback
- [ ] Freeze precedence: protected core builtins, Nift/user/imported/package callables, then PATH executable.
- [ ] Keep `foo(...)` explicitly Nift and `run(...)` explicitly external.
- [ ] Add `which`/equivalent provenance and sensible PATH caching/invalidation.

### CP19 — external-command globs
- [ ] Expand Nift globs before external spawn (`clang++ *.cpp`) portably.
- [ ] Define quoting/no-match behavior; prove platform equivalence.

### CP20 — `niftrc`
- [ ] Restore `niftrc` as ordinary modern Nift loaded by `nift sh`.
- [ ] Preserve old naming/location behavior where sensible.
- [ ] Support env setup/functions/imports; do not silently auto-run untrusted project-local rc code.

### CP21 — history
- [ ] Restore persistent shell history with sensible storage/bounds and tests.

### CP22 — tab completion
- [ ] Treat completion as a release requirement.
- [ ] Complete Nift builtins, user/imported/package functions, PATH executables and filesystem paths.
- [ ] `cd` completes directories; complete identifiers/members where reliable.
- [ ] Share indexes with command resolution; add deterministic tests.

- [ ] Freeze simple layout: `manifest.json`, Nift `.f` sources, tests, README.
- [ ] Make isolated `@import` + explicit exports deterministic/package-worthy.
- [ ] Distinguish local `@import("./local.f")` from package `@import("sqlite")`.

### CP31 — package acquisition
- [ ] Implement local paths and arbitrary Git/GitHub sources.
- [ ] Add `nift add`, `remove`, `install`, `update` with rollback/failure semantics.
- [ ] Git repos remain source of truth; test repeated/offline installs, bad manifests/refs and interruption.

### CP32 — refs + lockfile
- [ ] Support `latest-tag`, `latest` (default-branch HEAD), explicit tag/version, commit, useful branch refs and local paths.
- [ ] `latest-tag` uses semantic-version ordering, not tag date.
- [ ] Lock remote deps to exact commits; `nift update` deliberately advances floating refs.
- [ ] Report conflicts clearly before considering npm-style multi-version complexity.

### CP33 — centralized GitHub registry
- [ ] Use `nift-packages` org and/or a small Git-hosted index for short names.
- [ ] `nift add sqlite` resolves centrally; `github:user/repo` bypasses it; local paths remain first-class.

### CP34 — package/shell integration
- [ ] Package exports become ordinary Nift callables in templates/scripts.
- [ ] Exports participate in command resolution/completion automatically.
- [ ] One implementation supports both `resize("hero.jpg", 1200)` and `resize hero.jpg 1200`.
- [ ] Expose package provenance through `which`/introspection.
