# Nift v4.4.0 — execution, shell and packages

Status: **planned**. Start only after the v4.3.0 line is deliberately closed and the maintainer authorizes v4.4 work.

v4.4 turns the v4.3 language into a coherent execution environment: variadics, spread, wildcards, a real cross-platform shell, process interoperability, native build/project scripting, lifecycle hooks, and a Git-native Nift package ecosystem. The first package is `nift-packages/sqlite`.

## Campaign rules

- Expression calls stay `fn(a, b)`. Script/shell command calls may use `fn a b`; unquoted command arguments are literal tokens so `rm *.o` and `cp assets/**/* public/assets/` need no quotes. `$[...]` bridges command arguments back to evaluated Nift values.
- Variadics are general: user functions, lambdas and eligible native functions use trailing `...args` as an ordinary heterogeneous array; spread expands arrays into arguments.
- Define wildcard semantics once. Reuse them for `ls`, `cp`, `mv`, `rm` and external-command glob expansion. Structured-data wildcards are a separate contract.
- `cp`, `mv`, `rm`, `mkdir` are Nift-native aliases, not platform utilities.
- External execution uses direct executable + argv spawning, not `system()`/implicit Bash. Explicit Bash remains allowed.
- Command-style process syntax should match familiar Bash syntax where practical (`|`, redirections, `&&`, `||`, `&`, quoting/escaping, env assignment), while normal Nift syntax uses structured `run()`/`cmd()` APIs over the same process engine.
- Standalone scripting follows normal OS-user authority by default; restrictions are opt-in.
- Packages are Nift `.f` code. Do not reintroduce Lua/LuaJIT for packages.
- Every public behavior checkpoint accounts for source tests, independent regression coverage, website docs/examples and handover/decision updates.
- Preserve performance/RSS; guard against hidden O(n²) glob, PATH, package-graph and hook work.

```text
foo(a, b)                  # explicit Nift callable
run("foo", "a", "b")      # explicit external process
foo a b                    # command-style resolution in script/shell land
```

## Phase B — execution and filesystem authority

### CP10 — standalone filesystem authority
- [x] Separate build path invariants from `nift run`/`nift sh` authority.
- [x] Allow normal absolute/parent/home paths subject to OS permissions.
- [x] Preserve build dependency/output safety; prove distinction cross-platform.

### CP11 — process core
- [x] Implement direct executable + argv spawning on Unix (`fork`+`execvp`; `posix_spawnp` was the candidate but fork/execvp was used). Windows `CreateProcessW()` is not implemented.
- [x] Inherit cwd/environment/auth context so existing `git`, `gh`, SSH-agent/cloud auth works (verified against git in this review).
- [x] Return exit code/stdout/stderr; handle not-found/non-zero/termination (127/126/128+signal, structured result).
- [x] Do not make `system()` the primary implementation (direct spawn only).

### CP12 — `run`
- [x] Expose `run()` broadly unless restricted by invocation capability (`--no-process`/`NIFT_NO_PROCESS`).
- [x] Support `run("git", "status", "--short")` and spread arrays.
- [x] Separate captured programmatic output from interactive streaming (capture is the default; `stream` re-emits after completion, not true interactive streaming).
- [x] Permit explicit `run("bash", "-c", "...")`; test with controlled helper executables.

### CP13 — structured command/pipeline API
- [x] Keep `run(...)` as the convenient synchronous single-process API returning structured exit/stdout/stderr results.
- [x] Add a first-class command builder, `cmd(...)`, that does not execute until `.run()`.
- [x] Support real streaming OS pipelines in normal syntax, e.g. `cmd("git", "log").pipe(cmd("grep", "fix")).run()`, using real OS pipes for intermediate stages (verified with a 5 MiB intermediate stream).
- [x] Add structured stdin/stdout/stderr routing to files/streams, including truncate vs append, cwd and environment overrides. Timeout is not implemented.
- [x] Preserve per-stage process status/error information sufficiently for robust scripting and agents (final-stage exit status plus structured result).
- [ ] `.start()`/process-object/background-execution semantics are not implemented.

### CP14 — persistent shell state
- [x] `nift sh` owns cwd, typed Nift variables and string OS environment variables.
- [x] Child processes inherit cwd/environment.
- [x] Rationalize getenv/set/export/unset with existing `@getenv` (`getenv`/`setenv`/`unsetenv` in script land; `@getenv` remains template land).
- [x] Prove native state changes persist while child changes cannot mutate parent state.

## Phase C — command-style shell

### CP15 — command grammar
- [x] Add command-style calls only in standalone script/shell land.
- [x] Unquoted args are literal tokens/paths (`rm *.o`); quotes handle whitespace.
- [ ] `$[...]` injects evaluated values into command arguments — NOT implemented (documented in the plan but not claimed in docs).
- [x] Use Bash-compatible command-style quoting/escaping/token behavior wherever practical so existing shell knowledge transfers directly.
- [x] Keep normal expression syntax unambiguous and separate from command-land parsing.
- [x] Test assignments/operators/comments/calls/path punctuation ambiguities.

### CP16 — Bash-compatible pipelines and redirection
- [x] Support `cmd1 | cmd2` as a real streaming OS pipeline in command land.
- [x] Support `<`, `>`, `>>`, `2>`, and `2>&1` with Bash-compatible meanings where practical (adjacent `2>`/`2>>`/`2>&1` tokenize correctly).
- [x] Support `&&` and `||` conditional command chaining and preserve meaningful exit-status behavior.
- [ ] `&` background execution is NOT implemented; it fails explicitly rather than faking backgrounding (per CP40).
- [x] Support leading environment assignment such as `FOO=bar command` without mutating the persistent shell environment.
- [x] Ensure quoting suppresses glob expansion/redirection/operator interpretation as users and agents expect from Bash.
- [x] Parse command syntax into the same internal command/pipeline representation used by `cmd()`; do not maintain a second execution engine.
- [ ] Windows black-box parity fixtures pending Windows backend.

### CP17 — native aliases
- [x] Add `cp` -> `copy`, `mv` -> `move`, `rm` -> `remove`, `mkdir` -> `make_dir`.
- [x] Preserve pleasant `ls`, `cd`, `pwd`, `cat`, `touch`, `exists` forms.
- [x] Use Nift implementations/wildcards everywhere.

### CP18 — command resolution/PATH fallback
- [x] Freeze precedence: protected core builtins, Nift/user/imported/package callables, then PATH executable.
- [x] Keep `foo(...)` explicitly Nift and `run(...)` explicitly external.
- [x] Add `which`/equivalent provenance and sensible PATH caching/invalidation (lookup is direct; no cache).

### CP19 — external-command globs
- [x] Expand Nift globs before external spawn (`clang++ *.cpp`) portably (POSIX `glob`; Windows passthrough pending backend).
- [x] Define quoting/no-match behavior; prove platform equivalence (Linux exercised; Windows pending).

### CP20 — `niftrc`
- [x] Restore `niftrc` as ordinary modern Nift loaded by `nift sh`.
- [x] Preserve old naming/location behavior where sensible (`~/.niftrc`).
- [x] Support env setup/functions/imports; do not silently auto-run untrusted project-local rc code.

### CP21 — history
- [x] Restore persistent shell history with sensible storage/bounds and tests (`.nift_history`, 1000-line bound).

### CP22 — tab completion
- [x] Treat completion as a release requirement (deterministic `nift complete` engine + interactive TAB editor).
- [x] Complete Nift builtins (full surface after review fix), PATH executables and filesystem paths.
- [x] Complete identifiers, user functions, imported functions and structs through the live parser context; directory-aware completion (`/` suffix) and shell-safe quoting of completed paths.
- [x] `cd` completes directories; share indexes with command resolution; deterministic tests plus PTY/interactive tests.
- [x] Interactive TAB/readline-style integration: raw-mode line editor in `nift sh` with history arrows, `Ctrl-C`/`Ctrl-D` handling (Unix; Windows falls back to line-based input pending the platform backend).
