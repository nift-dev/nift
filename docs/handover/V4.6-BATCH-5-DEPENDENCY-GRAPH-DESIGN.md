## 1. Current-state audit

### 1.1 Model: direct-only today

- A project has `manifest.json` with `dependencies: {name: {source, ref}}`
  (direct deps only). A package manifest may ALSO carry `dependencies`.
- `src/PackageMetadata.h`:
  - `Manifest{dependencies: map<name,{source,ref}>}`.
  - `Lock = map<name,{source, requested, commit}>` — a flat, direct-only map.
  - `validate_lock`: **`lock.size() == manifest.dependencies.size()`** — the
    lock must exactly equal the manifest's DIRECT deps; there is no room for
    transitive entries.
  - `ref` semantics: `latest` (clone default), `latest-tag` (highest
    `v<semver>` tag via `compare_semver`), or an explicit tag/branch/commit.
    No semver ranges exist and none are proposed here.
- `src/CLI.cpp` (`package_add_cli`, `package_install_cli`, `package_remove_cli`):
  - `add`: adds one direct dep, `package_checkout` (git clone + detach +
    `rev-parse HEAD`), stages, commits via the journaled transaction
    (manifest + lock + package store together). **It never inspects the added
    package's own `dependencies`.**
  - `install`/`update`: iterate the manifest's direct deps; for remote deps
    `package_checkout` is run again even when the lock already pins the exact
    commit (no reuse of an already-installed matching store slot). No closure.
  - `remove`: removes one direct dep + its store slot. No orphan handling.
- `src/PackageTransaction.cpp`: a journaled, crash-recoverable, atomic
  transaction. `create_staging` → validate staged identities → journal →
  backup old → promote → publish manifest+lock → verify → cleanup. Strong
  foundation: transitive resolution must fit inside it (stage the whole
  closure, commit together).
- Runtime resolution (`src/ParserScript.cpp` `execute_import_file`): a bare
  name is a package import resolved from the installed store root
  (`.nift/packages/<name>`); the installed manifest + entry are validated
  (Batch 4: `package.not_installed` recoverable, `package.manifest_invalid`
  fatal, `package.import_source_unreadable` recoverable). Package modules
  retain frozen lock provenance.

### 1.2 Confirmed gap (empirically reproduced)

A local package `a` declaring `dependencies: {b: {...}}`:

```
nift add /path/a      -> installs ONLY a
.nift/packages/       -> [a]   (b missing)
import("a"); afn()    -> error: undefined callable: bfn   (a's entry imports b from b)
```

The transitive closure is never resolved, installed, or locked. The lock is
strictly direct-only.

### 1.3 Registry state

`nift-packages/` (official org, 21 packages) contains **no real transitive
dependencies** — all are leaves. The one `dependencies` entry in the wild is
`sqlite`'s self-referential local artifact (an unrelated dirty repo we do not
touch). Transitive resolution is therefore greenfield: existing packages do
not yet rely on it, which lowers migration risk.

## 2. Design options / tradeoffs

### 2.1 Lockfile representation

- **Option A — flat closure lock:** `packages.lock.json` holds one entry per
  package in the closure (direct + transitive), plus a `requiredBy`/`paths`
  field. Simple to read, but edges are duplicated and "which path" must be
  recomputed.
- **Option B — graph lock (recommended):** each lock entry gains its own
  `dependencies` edge map (the resolved refs of that package's declared
  deps), mirroring package manifests. The lock becomes the exact resolved
  DAG. Paths are derivable; per-entry identity is unchanged; the format is
  forward-compatible and self-describing. Matches the README's "graph-shaped
  transitive locks".
- **Option C — separate lock sections:** `direct` + `transitive` arrays.
  Extra split for no benefit; more validation surface.

**Recommendation: B.** Root manifest stays direct-only (backward compatible);
the lock is the resolved closure DAG. A `"lockfileVersion": 2` field
distinguishes graph locks from the implicit v1 direct locks.

### 2.2 Resolution determinism and ordering

- Resolve deterministically: start from root direct deps **sorted by name**;
  recursively read each package's manifest deps **sorted by name**; resolve
  each `ref` to an exact commit; emit the lock **sorted by name** (the
  transaction already sorts operations by name).
- Two-phase: (1) compute the full closure + resolved commits (network/git
  only during this phase); (2) stage every package in the closure and commit
  atomically. Any failure in (1) or (2) aborts with no partial state.

### 2.3 Dedup, cycles, conflicts

- **Dedup:** the same `(source, ref)` resolves to one commit; multiple
  require-ers share one installed slot. The store stays `name`-keyed (one
  version per name — v1 does **not** support parallel versions of the same
  package in one closure).
- **Conflicts (deterministic error):** two requirements for the same `name`
  that resolve to different commits (or different sources for the same name)
  is a genuine conflict → fatal error naming both dependency paths. This is
  deterministic and explicit; it matches Nift's strict-metadata philosophy
  and lets the tool answer "which path required it".
- **Cycles:** a cycle in the declared graph → fatal error (no finite closure).
  Self-referential local deps (the sqlite artifact) are not a supported
  pattern and are rejected deterministically. (Rejecting them may surface the
  sqlite manifest as a latent issue; that is acceptable and documented — we
  do not touch that repo.)
- **Ref collision:** if two different refs for the same `(source, name)`
  resolve to the same commit, they deduplicate (not a conflict).

### 2.4 Version/ref interaction

- Ref semantics are unchanged (`latest`, `latest-tag`, explicit tag/branch/
  commit, `local`). **No semver-range resolution is added** — out of scope.
- `latest`/`latest-tag` resolve at `add`/`update`; the lock pins the exact
  commit. `install` with a valid lock uses the pinned commits (no
  re-resolution).

### 2.5 Cache and offline

- Current behavior re-runs `git clone` for every remote dep on every
  install/update even when the lock pins the commit.
- **Recommended v1:** reuse an already-installed store slot whose locked
  commit and identity match (skip re-fetch); only fetch when the commit
  differs (update/add/new). Optionally a content-addressed clone cache in
  `.nift/` — defer the cache to a later sub-checkpoint unless the closure
  work makes it necessary (decide at the first performance gate).
- **Offline:** imports from an installed, locked store work without network
  (today already true). `install`/`update` that need a missing package fail
  with a clear error; reuse-if-commit-matches makes offline `install` succeed
  when the closure is already present.

### 2.6 Command effects

- `add <source>`: adds the direct dep and installs its **closure**.
- `install`: ensures the whole locked closure is present (fetching only what
  is missing/mismatched).
- `update [name]`: re-resolves the floating refs of `name` **and its
  transitive closure** to new commits; pins and stages the changed set.
- `remove <name>`: removes the direct dep and **deterministically removes
  orphaned transitive packages** (those no longer required by any remaining
  closure member), atomically.
- All operations keep the journaled atomic transaction.

## 3. Recommended contract

1. **Manifest:** unchanged (root declares only direct deps; package manifests
   may declare their own deps — now honored).
2. **Lock (v2 graph):**
   ```json
   {
     "lockfileVersion": 2,
     "a": { "source": "github:org/a", "requested": "latest", "commit": "<40hex>",
            "dependencies": { "b": { "source": "github:org/b", "requested": "latest",
                                     "commit": "<40hex>" } } },
     "b": { "source": "github:org/b", "requested": "latest", "commit": "<40hex>",
            "dependencies": {} }
   }
   ```
   `local` sources keep `"commit": "local"`. Every installed package appears
   once; every edge mirrors a declared manifest dependency of the parent.
3. **Resolution:** deterministic sorted walk; dedup by name; conflict and
   cycle → fatal error with paths; pinned commits recorded.
4. **Identity/provenance:** unchanged — name from the manifest `name` must
   equal the dependency key; the store slot is `.nift/packages/<name>`;
   remote slots are detached at the pinned commit and verified (existing
   `detached_git_head` check); package modules keep frozen lock provenance.
5. **Atomicity:** the full closure is staged and committed via the existing
   journaled transaction; a failure anywhere rolls back to the prior
   manifest+lock+store.
6. **Reproducibility:** identical root manifest + same remote state →
   identical lock and store. Local-path deps remain machine-local by nature
   (absolute paths) and are documented as non-portable across machines.
7. **Batch 4 interaction:** a missing/unreadable closure member at runtime
   stays a recoverable `package.not_installed` /
   `package.import_source_unreadable`; malformed transitive metadata or lock
   inconsistency stays fatal (`package.manifest_invalid` /
   `package.lock_invalid`). Resolution-time malformed metadata is a fatal
   resolve error.

## 4. Step-by-step checkpoint plan

- **CP10 — lockfile + validate (format only):** extend `PackageMetadata.h`
  with a v2 graph lock (per-entry `dependencies`, `lockfileVersion`); relax
  `validate_lock` to "every manifest dep present with matching source/ref; the
  lock is a superset (the closure)"; migrate/load v1 direct locks. No resolver
  behavior change yet. Gate: package metadata + hardening + existing
  transaction walls stay green; old direct locks still validate.
- **CP11 — deterministic closure resolver (compute-only):** a `resolve`
  module that, given the root manifest + a resolution callback (local resolve
  from disk; remote resolve reusing `package_checkout`), computes the sorted
  closure DAG, dedups, detects cycles, reports conflicts with paths. Unit
  coverage for the graph algorithm independent of git. Gate: new unit wall;
  no CLI behavior change (still not wired into commands).
- **CP12 — wire closure into add/install/update/remove:** `add` stages the
  closure; `install` ensures the locked closure (reuse-if-commit-matches);
  `update` re-resolves the closure; `remove` orphans. All inside the existing
  transaction. Gate: end-to-end package walls (local + git fixtures,
  transitive success, orphan removal, rollback).
- **CP13 — determinism/reproducibility certification:** identical-lock
  assertion across two cold installs; cross-machine note for local paths;
  `nift info`-style path query for "why is this installed / which path";
  offline install with complete store; conflict and cycle walls. Gate:
  full Batch 4 + package walls + sanitizers.
- **CP14 — campaign certification:** aggregate gate + evidence + review; the
  final Batch 5 boundary.

## 5. Explicit review gates

- Gate CP10: existing package metadata/transaction/hardening/refs walls green;
  v1 direct locks still load; new v2 format parses and validates; no resolver
  change.
- Gate CP11: resolver unit wall green (determinism, dedup, cycles, conflicts,
  ordering); the compute-only contract is reviewed before wiring.
- Gate CP12: full package end-to-end walls green (add/install/update/remove
  with transitive closures, local + git sources, atomic rollback, orphan
  removal); Batch 4 aggregate green.
- Gate CP13: reproducibility/determinism certification green; offline +
  conflict + cycle walls green; sanitizers green.
- Final: full Batch 5 aggregate + independent review over the whole range;
  commit boundary; then the campaign is closed (no push without explicit
  approval).

## 6. Compatibility risks

- **Existing direct-only locks** must keep validating (relax the strict size
  equality; superset check). Old v1 locks are a valid closure with no
  transitive entries.
- **Existing package commands** keep their semantics for direct deps; only the
  closure behavior is added.
- **`install` fetch behavior change** (reuse-if-commit-matches) alters
  current always-re-clone behavior — must be certified not to regress lock
  identity verification (detached-git-head stays).
- **Conflict/cycle errors** are new fatal outcomes; existing leaf packages are
  unaffected (no deps → no conflicts).
- **Local absolute paths** in lock entries remain non-portable; documented.
- **The sqlite self-referential manifest** would fail a cycle check — we do
  not modify that repo; the v1 direct-only path that tolerates it today is
  preserved only if it is not part of a resolved closure (documented; the
  sqlite package is dogfood/legacy).

## 7. Test matrix

- **Metadata/format:** v2 graph lock parse/validate; v1 → v2 load; malformed
  graph entries (bad commit, missing edge, cycle, unknown field).
- **Resolution (unit):** determinism (sorted walk, stable order); dedup
  (shared commit); conflict (different commits / different sources, two
  paths reported); cycle (A→B→A, self); refs (`latest`, `latest-tag`,
  explicit, `local`).
- **End-to-end:** `add` transitive success (local + git fixtures); `install`
  closure + reuse-if-commit-matches + offline-with-full-store; `update`
  closure re-resolution; `remove` orphan removal + retained-when-required;
  rollback on a mid-closure failure (no partial manifest/lock/store).
- **Runtime/provenance:** package import of a transitive member; frozen lock
  provenance through workers; Batch 4 recoverable (`package.not_installed`
  when a member is deleted) and fatal (`package.manifest_invalid`,
  `package.lock_invalid`) outcomes.
- **Reproducibility:** two cold installs produce byte-identical lock; path
  query answers "why/which path/source-version-ref".
- **Compatibility:** existing leaf packages and v1 locks unchanged; full
  Batch 4 + existing package walls green.
- **Sanitizers/concurrency:** ASan/UBSan/TSan over the closure staging and
  the transaction paths.

## 8. Explicitly out of scope (v1)

- Semver-range resolution (`^1.2.3`, `~1.2`).
- Parallel versions of one package in a closure.
- A global package cache (deferred; decide at CP12 perf gate).
- Registry server / index protocol changes (bare names continue to map to
  `github.com/nift-packages/<name>.git`).

No implementation begins until this plan is reviewed. No tag/release. The
unrelated `nift-packages/sqlite` repo is not touched.
