# v4.5 CP27 — Embedding concurrency and isolation certification

Certification now covers concurrent independent Engines, concurrent calls into one Engine script runtime, trusted host callbacks, async teardown, and the pre-existing concurrent render/reload contracts.

- Separate Engines own independent Parser/script state, invocation bindings, targets, host-function maps, FFI resource registries, threads and futures.
- Script operations on one Engine are serialized by the Engine script-runtime mutex. This is deliberately stronger and easier to reason about than allowing simultaneous mutation of one Parser.
- Render/reload concurrency retains the existing snapshot/cache contract and is independent of the script-runtime mutex.
- `execute()` finalizes owned thread/async work before returning; Engine destruction therefore cannot leave language workers using a destroyed runtime.
- FFI handles are Parser-local resources and are automatically closed with that runtime; ordinary thread/async transfer rules reject opaque FFI resources.
- Host callable registration is mutation and must happen outside active calls. Registered callbacks execute synchronously under the owning operation.

The dedicated CP27 test runs isolated Engines in parallel and many host→Nift→host calls against one shared Engine. Existing Engine concurrency/reload suites remain mandatory. TSan remains a release-wall gate; platform CI is authoritative where the local environment cannot execute a sanitizer/runtime combination.
