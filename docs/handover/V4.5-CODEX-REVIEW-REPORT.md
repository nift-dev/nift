# Nift v4.5 independent Codex review report

Date: 2026-09-27

## Executive result

The v4.5 candidate is **ready to continue toward release with remaining CI and
warning gates**. It is not ready to tag or publish yet.

This pass found no reproducible v4.5 runtime correctness or sanitizer defect in
the exercised Linux surface. It did find four certification defects: three
maintained v4.4 tests still invoked the deliberately removed `nift run`/`nift
sh` entry points, the independent runner did not preserve documented relative
artifact paths after modules changed directory, and the historical independent
contract still asserted the v4.4 version. All were repaired and committed with
focused regressions/reruns.

Remaining release gates are native macOS/Windows execution, a usable LSan host,
the ptrace-dependent pagination ordering check, and deliberate warning cleanup.

## Repairs and commits

### Nift source repository

- `94bf935 Update stale v4.4 invocation tests`
  - Reproduction: `make -k test` failed in `v44_ast_expression_smoke.sh` and
    `v44_cp21_history_smoke.sh`; source inspection found the same stale command
    in `v44_ast_differential_corpus.sh`.
  - Root cause: CP3 removed `nift run` and `nift sh`, but these maintained v4.4
    tests were missed by the migration.
  - Repair: use direct file invocation and the zero-argument REPL.
  - Regression: all three focused scripts pass.
- `4797c34 Eliminate actionable compiler warnings`
  - Audited every GCC/Clang diagnostic, including v4.5 parser, FFI, embedding
    and CLI paths; fresh optimized builds are warning-clean on both compilers.
- `1d1fb4d Repair v4.5 C ABI certification tests`
  - Corrects the maintained adversarial assertion from stale ABI 1.0 to the
    supported ABI 1.1 and makes the standalone FFI fixture self-contained by
    creating its build directory. `make test-embed` and staged C/C++ consumers
    pass afterward.

### Independent regression repository

- `c92dafb Canonicalize contract artifact paths`
  - Reproduction: the documented
    `NIFT_BIN=../nift/nift NIFT_EMBED_PREFIX=../nift/dist/embed-prefix
    ./run-contract.sh` produced 61 false module failures after modules changed
    directory.
  - Root cause: `command -v` accepted a relative path containing `/` without
    canonicalizing it; the embed prefix was not canonicalized either.
  - Repair: resolve executable paths containing `/` and the optional embed
    prefix to absolute paths at the runner boundary.
  - Regression: the exact documented relative-path invocation passes all 77
    modules.
- `42388cd Update legacy contract version assertion`
  - Reproduction: after fixing artifact paths, 76/77 modules passed and the
    historical module failed only because it required `v4.4.0`.
  - Repair: assert the v4.5 candidate identity.
  - Regression: historical corpus passes 574/574 assertions; complete runner
    passes 77/77 modules.

## Review findings

- CLI/parser: direct files, inline/stdin identity, platform option ordering,
  `--`, async/await syntax and atomic operators are covered by focused and
  independent tests. The stale maintained invocation tests above were the main
  coverage drift found.
- Shell/jobs: maintained and independent background/job-control modules pass on
  Linux. Interactive terminal behavior still requires native platform CI and
  real-terminal dogfood.
- Threads/mutexes/atomics/futures: focused, integration, ASan/UBSan and TSan
  walls pass. The TSan wall included all four primitives and the adversarial
  runtime corpus with `halt_on_error=1`.
- FFI: scalar/handle/signature fixture and buffer/callback/lifetime tests pass,
  including ASan/UBSan execution with leak detection disabled.
- Embedding/C ABI: staged C and C++ consumers pass against installed headers and
  libraries. ABI reports 1.1 through the maintained binding tests. Go, Python,
  Node and C# bindings pass.
- Isolation/teardown: maintained C# tests include concurrent render/dispose and
  in-flight lifetime cases; focused native adversarial tests pass. No defect was
  reproduced.
- Warnings: the follow-up audit traced every GCC/Clang diagnostic to source,
  repaired the actionable v4.4/v4.5 cases, added the missing `StrNumber`
  handling, removed the dead FFI condition `rt == "void" && false`, and made
  aggregate initialization explicit. Fresh optimized GCC 15.2 and Clang 21.1
  builds now complete with zero warning lines (`4797c34`).
