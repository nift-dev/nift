## 5. Release-workflow audit

- `release.yml`: tag-triggered (`push: tags: v*`); `permissions: contents: write`;
  unix matrix (ubuntu-latest, macos-15, macos-15-intel) + windows (msys2 UCRT64,
  static, no-mingw-DLL check); `installer-preflight` (`make test-installer`);
  `publish` uses `GITHUB_TOKEN` with `gh release create --verify-tag
  --generate-notes` and an idempotency guard; `installer-public-smoke` ×3.
- `snap.yml`: publication gated on `refs/tags/v` + `secrets.SNAPCRAFT_STORE_CREDENTIALS` presence.
- `chocolatey.yml`: publication gated on non-PR + `secrets.CHOCOLATEY_API_KEY`.
- `homebrew.yml`: builds/tests the formula; no credentials; propagation is
  Homebrew's automatic bump service (no manual PR).
- `distribution-verification.yml`: separate, run post-release once stores propagate.
- No PR-triggered publishing workflow can reach credentials. Secret scan of
  tracked files and history found only `${{ secrets.* }}` references, no values.

## 9. Normal package-channel execution plan (CLI-RC05/RC06)

1. `v4.0.7` annotated tag → `release.yml` (unix ×3, windows, installer-preflight,
   publish, installer-public-smoke ×3).
2. Snap: `snap.yml` build + Publish stable (amd64 + arm64), gated on tag + credential.
3. Chocolatey: `chocolatey.yml` package + publish (moderation is a downstream state).
4. Homebrew: `homebrew.yml` builds/tests the formula; automatic-bump propagation

6. `distribution-verification.yml` once stores propagate.
Deferred (not a 4.0.7 gate): npm/PyPI/NuGet/crates.io binding publication.
