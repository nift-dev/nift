# Nift ownership and dispatch designs for review

## Callable environment alternatives

A. Retained copied maps (current): fresh identity, factory effects, complete all-visible descriptor snapshots and shared live slots; instance and invocation each pay map construction. Safe oracle, expensive.

B. Scope-wide snapshot/overlay (measured private implementation): complete descriptor equality, duplicate-shadow detection and slot/root ownership checks, immutable shared map with per-frame mutable overlay. It passes targeted identity/capture/origin/async contracts but regresses ordinary lookup controls, and only saves ~14% on ordinary sort. Drop this implementation.

C. Callback-specific persistent environment (design): keep ordinary mutable scope maps unchanged. Scope mutation creates a new immutable descriptor-version node; each callable records the current version and a fresh identity, while captures point at existing live slots. Parameter/local frame entries form a separate overlay. Resolve the local frame, then the captured version for snapshotted names. Names absent at creation must retain the existing later caller/global fallback; this is not a closed lexical environment. Preserve module/global named-callable precedence and injected cmd/args redeclaration exceptions. Root-path descriptors must preserve the exact owner and path snapshot independently of current scalar value. Explicit rebinding, declaration, shadowing, scope push/pop, aliases, readonly flags, module ownership and command bindings advance the descriptor version; writes through a live slot must not accidentally freeze values. Uncontrolled mutation paths must be enumerated before implementation. Cache successful resolution to stable descriptor slots only with version identity, not raw map pointers. This avoids copies while allowing registry retention; no escape heuristic is required. A persistent trie/index can avoid cloning the complete map on every mutation, but its lookup/mutation cost must beat the dropped overlay and pass ordinary controls.

D. Prepared selector invocation frame (design): each fresh factory invocation still executes and registers a distinct identity. Store an immutable callable plan for origin/body/parameter metadata independently of each instance. The instance stores environment-version ownership plus distinct identity/state; callback invocation allocates only mutated locals, parameter locations and alias bookkeeping required by the actual plan. An invocation frame cannot outlive its operation unless promoted through an explicitly owning context; current reconstructable identity tags mean instance registry ownership remains until Parser teardown. Slot addresses and references exposed to nested closures require stable owned locations, never reusable stack references. Reuse allocations only when no observable alias can survive; cannot infer this from local variable disappearance.

## Shared filesystem backend

Introduce an internal resolved-operation value that holds evaluated operands, operation-local base path, validation authority and resolved source/destination paths. Direct operations consume it without reconstructing source strings or reparsing arguments. Resolve cwd after operand evaluation; cwd may change through cd/FFI, so a Parser-global cache is unsound. Keep globs, tilde expansion, project/root authority, destination-directory behavior, typed recoverable errors, partial multi-source effects and cross-filesystem rename errors exact.

The scratch c.call implementation is intentionally success-only and private. Its initial guard wrongly required filesystem validation to be disabled, while CLI validation is enabled even with an empty allowed root. That disabled-backend result is discarded as a routing inference. The corrected empty-root gate reduces original move/copy instructions about 2.9× and stat 1.3×, but a side-effect probe changes four evaluations to two. A production design must cover compatibility evaluation and prepared loops, with one shared backend and source-span-aware diagnostics. Preflight supported lowering before operand evaluation. Preserve the currently observed speculative-then-fallback side effects wherever they are part of the compatibility path, or obtain explicit approval for a language correction. Do not silently switch to single evaluation under a performance label.

## Strings and source preparation

An 8 KiB source ceiling routes long literals through repeated textual interpretation. A scratch 64 KiB ceiling, preserving nesting depth, plus direct value replacement gives ~6.1× fewer instructions on the exact pure large fixture. This is not a certificate for increasing a safety boundary. Prefer a bounded token/plan representation that measures syntax depth and dynamic node count separately from literal byte payload; retain source spans and original error precedence. Cache immutable literal values in the plan rather than repeatedly decoding text. Apply direct methods through the shared value backend. Preflight/purity rules must avoid removing observable fallback effects; a semantic change requires separate approval.

## Closed file and save state

Retain identity shells, path/mode and reopen state because tags can be reconstructed after scopes exit. Release heavy state only at a proven lifecycle boundary; close must retain exact dirty-error behavior and aliases. A shared immutable successful-save snapshot plus copy-on-write working state can remove two full buffer owners, but every mutable operation, revert/open mode and externally changed file behavior needs a certificate. Dirty generation alone is insufficient if an operation restores bytes to the saved value. Atomic replacement, permissions, parent checks, temporary cleanup and error paths remain part of the backend. The measured clear-and-shrink prototype regresses CPU and is dropped.

## Runtime object indexes

All indexes are keyed by owned strings and store vector indices, not pointers. Preserve ordered iteration and first-duplicate lookup. Existing value writes leave a membership index intact; append updates it, erase repairs first duplicates and shifted indices, arbitrary vector replacement invalidates it. The public object vector currently permits mutations outside a centralized gateway; a persistent index is unsound without encapsulation or an audited invalidation contract. Lazy/threshold/operation-local models offer huge repeated-wide lookup gains but cold-copy rebuilds are 5–6× slower. Consider shared immutable key-order metadata only if mutation can invalidate it reliably; copy-heavy one-lookup workloads should stay vector-only or defer promotion until enough reads amortize construction. No representation change is authorized by prototype speed alone.
