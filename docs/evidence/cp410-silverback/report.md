# NIFT v4.10 — SILVERBACK PERFORMANCE REVIEW

The strongest measured Nift-owned opportunities are source preparation/value dispatch, shared path-prefix resolution, and wide RuntimeValue object indexing. Sort remains the primary product target, but the measured scope-wide snapshot implementation is rejected: its ordinary sort gain is small and its scalar-call/loop regressions are material. A callback-specific persistent environment needs deliberate implementation and proof before a production architecture commit. The public performance gaps remain open; local controls do not update the frozen official series.

## Scope and decisions

Keep the separately certified single-scan glob and linear string-builder tranche (`34dfe75679a82dc3a54a54c038f543a3e960f754`). Its full local safety certificate, NRS/PRS and real-build parity are in `../cp410-wave3/report.md`. Windows fixture transport errors were deterministic and corrected rather than labelled flaky; final hosted receipts must refer to the final SHA containing the guard correction.

All new architecture code in this review is private scratch research. No callable ownership, registry reclamation, RuntimeValue representation, prepared-source limit or filesystem backend change is promoted. Jsonic++ is dropped from this campaign at the user's explicit instruction. Its canonical header/tests are restored to their pre-campaign HEAD; consumers and synchronization policy were never changed. The specialized strict-wide-object evidence is archived only and is not evidence that normal Jsonic++ parsing is slow.

## Ranked recommendations

1. **Sort / selector environments and frames.** Preserve fresh factory execution and identity, but separate immutable callable plans and persistent descriptor environments from fresh instance identity and invocation overlays. Keep ordinary scope lookup unchanged. The local sort decomposition admits about a 4.1× ideal whole-fixture instruction ceiling if setup stays unchanged; a 2–3× target is plausible, not demonstrated. Do not revive the dropped general scope wrapper. Retention alone is not the decisive cause and cannot be removed by local escape guesses.
2. **Traversal canonical-prefix sharing.** Pursue operation-local resolved directory prefixes and terminal result materialization with a full glob state machine. The stable-filesystem native control gives a measured roughly 1.84–2.36× CPU floor improvement versus current Nift, before integration costs. Preserve absolute pre-canonical sort/dedup, symlink leaves and error fallback; prove concurrent filesystem behavior or state the required contract explicitly.
3. **Save lifecycle and shared value/filesystem execution backend.** Move the common source parsing, argument evaluation and path validation into a prepared operation recipe consumed by both compatibility and prepared evaluators. Atomic close/rename remains mandatory. A 2× CPU target versus current 100k small-file saves is plausible from the historical atomic floor, but current scratch backend has not demonstrated it on the original compatibility-loop fixture. Buffer shrinking is rejected.
4. **Stat / move / copy and concat through the same backend.** Current successful local instruction ratios are about 8.9× / 36.6× / 34.3× / 8.7× native controls. There is substantial Nift-owned machinery to remove. A backend only reached by already-prepared calls barely helps the original loops: execution-path coverage is essential. Target 2–5× initially; 10× whole-program improvement is unproven and constrained by kernel work and full contracts.
5. **String preparation and evaluated-value methods.** A private larger source-preparation limit plus direct replacement gives 6.1× fewer instructions and roughly 4.6× CPU improvement on the exact pure large-string fixture. It changes side-effect counts on non-pure receivers/arguments, so production requires a preparation/preflight design preserving compatibility or an explicitly approved language correction. Increasing a safety limit alone is not certified.
6. **Nift RuntimeValue object indexes.** At 8k width, repeated reads/writes are about 114–115× fewer instructions with lazy/thresholded indexes, but cold copies with one lookup are about 5.3× slower. This is a 10×+ lookup-subsystem candidate, not a whole JSON workload claim. Threshold and access-count promotion need workload evidence, reliable mutation invalidation and architecture approval. Jsonic++ is outside this item.

## Sort semantics, models and lower bound

Three lower-bound ownership models at 16k perform the same identity keys, stable sort, result reconstruction and distinct retained integer identities: key-only 3.51M instructions, shared-environment retained instances 3.91M, copied-environment retained instances 48.54M with no unused bindings (796.42M with 100 unused bindings). These simplified models exclude rich VariableBinding descriptors, source/module ownership, factory execution, aliases and language dispatch; they establish a mechanism, not an exact semantic implementation or 100× achievable speedup.

The actual private scope-wrapper prototype retains complete all-visible captures, shared live slots, metadata/owner equality and duplicate-shadow checks. Its corrected v2 ordinary identity sort is 380.7M versus 442.8M (~14%); capture-heavy unused-100 cases improve roughly 72–74%. Targeted sort, capture, origin, root/alias and async contracts pass. Ordinary loops regress 7.5%, scalar calls 5.4%, and callbacks are neutral. **DROP** production. `design.md` specifies callback-specific persistent descriptor versions and plan/instance/frame separation without imposing indexed lookup on ordinary scopes.

Fresh factory side effects, distinct identity and all-visible capture descriptors are unavoidable under the current contract. Captured names snapshot descriptor membership but retain live slots; previously absent names can still resolve from later caller/global scopes, and named-callable/module precedence plus injected cmd/args redeclaration rules must remain. Complete map copying and metadata repetition are not inherently required. Registry retention is observable: after a function's locals vanish, constructing the bytes for `\x1fnift:callable:lambda:1` still calls the retained lambda and yields `7`. An analogous closed file tag still reports its path, reopens and reads `abc`. Operation-owned reclamation or promotion-on-escape based on normal references would break these tests. An opaque owning-handle contract would be a separately approved language change.

## Traversal operation model

For the 120k stable fixture, both Nift and equivalent canonical native scan directories once (173 getdents64 calls), perform one final absolute lexical sort and one deduplication pass. Nift does ~240k metadata calls and 1,200,016 readlink calls; canonical native does ~240k metadata and 1,200,008 readlinks. Thus the old native control reproduces the same canonicalization tax. External find-style controls that omit canonical presentation are not contract-equivalent.

The prefix prototype canonicalizes a common directory once, caches a shared immutable prefix, and resolves symlink leaves individually. Relative-root v2 reduces readlinks to 17 and metadata calls to ~120k; it still has a preventable cwd call per absolute-result construction. Final v3 resolves the traversal root once as current Nift already does. It measures 3,439,955,379 instructions, 4,680,054 allocations and 850,724,076 cumulative bytes, with zero Memcheck errors and zero exit heap. Six alternating isolated pairs give current/prefix median CPU 1.65154/0.89534 s (wide, 1.84×), 2.54919/1.08093 s (deep, 2.36×), and 1.47598/0.68646 s (mixed, 2.15×). Wide RSS is 205,848/146,252 KiB; mixed prefix RSS is slightly higher than Nift, so memory gains are shape-dependent. Stable ordered outputs match mixed aliases/dangling links, deep and wide fixtures. Result materialization remains one string per result; Nift additionally owns a RuntimeValue wrapper per result. Both sort keys are computed once per result; the prototype adds one shared prefix reference per match. Exact path/string construction counts are not comprehensively instrumented, so no invented operation ratios are claimed for those categories.

An initial full-canonical-path hint duplicated result paths and was slightly worse (3,825M instructions); **DROP** that model. Shared prefixes avoid that duplicate owner. RSS and allocations are recorded independently. The prototype is a fixed recursive suffix control, not a certified general glob engine, and does not prove symlink retarget/error behavior under concurrent mutation.

## Save phases and lifetime

The instrumented 1k-file model reports CheckedPath 22.74M instructions (including PathResolution 20.45M and Cwd 2.87M), Save 10.73M (including ParentCheck 2.61M, TempName 3.39M, Stream 2.86M), FileConstruction 1.51M, Registry 0.55M and retained-file teardown 1.77M. These are inclusive, overlapping, hooked totals, not additive fractions of unhooked 214.5M. The teardown hook explicitly moves file-registry clearing into a measured private destructor phase; it does not measure total Parser teardown.

Unhooked historical accepted save profiles show source-call parsing, string comparisons/scanning and interpretation among the largest self-costs, outside file-method phase bodies. At 100k files, path resolution makes ~2.8M allocations; successful stream save allocates 100k 8KiB buffers (~819MB cumulatively), while saved-state duplication is ~12.9MB cumulatively. Registry/instance construction and retained path state are significant. Releasing string capacity alone reduces RSS 171,910 → 144,614 KiB (15.9%) but regresses CPU 5.039 → 5.224 s (3.7%): **DROP**. Do not delete closed shells or treat a generation counter as exact content equality.

Keep atomic temp write/flush/close/permissions/rename, dirty-close errors, revert and reopen behavior, and aliases. A shared immutable post-save buffer plus copy-on-write working state is a design candidate; every write/append/revert/open mode and externally changed file boundary requires tests before promotion. An operation-local resolved context can avoid repeated conversion/validation; global cwd caching is unsound because cd/FFI can change cwd.

## Filesystem backend experiment and strings

The private value-call stat/move/copy context uses one cwd snapshot and evaluated plain arguments under an unrestricted standalone success-only fixture. It produces identical files/output but saves essentially nothing on the original for-loop workloads (stat 43.283M → 43.283M; move 228.572M → 228.380M; copy 230.129M → 229.834M). This is an execution-path miss, not evidence that wrapper overhead is unavoidable. Errors, source spans, fallback effects and restricted-root/glob/tilde cases are deliberately uncertified; no production commit.

String small pure fixtures improve 2.9–4.1× instructions with direct methods. The original large expression is above the prepared parser's 8KiB source ceiling, so direct methods alone do not help it. A scratch 64KiB ceiling with the nesting guard unchanged yields 5.23B; adding evaluated-value replacement yields 1.35B versus 8.19B. Actual counterexamples show argument and receiver factory side effects changing from four executions to two. Eight isolated alternating pairs on the pure large-string fixture give median CPU 0.34930 → 0.07674 s (4.55×), with comparable RSS. General single-evaluation adoption is therefore a semantic decision, not a safe optimization. `design.md` outlines bounded literal-aware preparation and preflight before operand evaluation.

## Object index models and proof boundaries

All 120 instruction cases compare four strategies (vector, lazy, threshold-128 hybrid, threshold-32 operation-local) across widths 8/32/128/512/2k/8k and reads/writes/iteration/mutation/copy-move. All output checks and 120 independent Memcheck cases pass, including permanent scratch first-duplicate erase/append and copy isolation checks. 8k hybrid reads/writes are ~115×/~114× fewer instructions; 8k mutation ~1.64×; cold-copy one-lookup ~0.19× (5.3× slower). Iteration stays on the ordered vector. Width-8 indexing is slower; thresholding avoids construction there. Final ordinary allocator counters measure the actual operation, independently of Memcheck interposition.

The 8k index costs 8,002 allocations and ~513KB owned membership payload. Cold copies rebuild 16 indexes: 128,048 operation allocations versus 16 vector allocations, ~31.76MB versus ~23.55MB cumulative bytes. Short-process RSS is descriptive and includes fixture/runtime startup, not an acceptance percentage. The current public object vector permits uncontrolled external mutation; adding a persistent index without central invalidation would be unsound. Seek architecture approval only for a usage-aware, copy-aware design after real Nift object-heavy workloads demonstrate amortization.

## Payoff classifications

- **2×+ candidates:** callback-specific sort environment/frame design (plausible, unproven); stable traversal prefixes (measured control); shared prepared filesystem backend/save (plausible, current routing prototype misses original loops); string preparation/value methods (measured pure cases).
- **5×+ candidates:** large-string instructions (6.1× measured; CPU ~4.6×); broader filesystem userspace instruction reduction (headroom only); repeated wide RuntimeValue lookup (measured).
- **10×+ candidates:** repeated wide RuntimeValue lookup subsystem (114–115× measured); potentially filesystem wrapper instruction paths (34–37× native ratios, no certified implementation). No demonstrated 10× general Nift application improvement.

The recommended next implementation checkpoint is sort plan/environment/frame design, with ordinary lookup controls unchanged, alongside a source-aware shared value backend that reaches the actual compatibility loops. Do not run official benchmarks or alter frozen evidence to claim these research projections as shipped performance.
