## H2 exec semantics

The launcher forks every stage before reading any exec-report pipe. The
reports are applied by stage after all forks. Added Host tests cover exec
failure in the first, middle and last stage, all stages failing, and the
report read end being closed early. Existing 127/126 messages, statuses,
cleanup and fd ownership are unchanged; `pipeline_exec_failures` and
`exec_report_closed_early` pass. Low-fd pipelines still pass at `-n 8`
(3 stages) and `-n 10` (8 stages).

## Intentional differences (D5, corrected)

- `2>&1 |` accepted by scripted CP20 (required capability); interactive
  foreground remains legacy and keeps its old syntax result.
- Host stdin/stdout open failures include richer diagnostics; pre-CP20 was
  silent.
- Missing `#!` interpreter names the actual interpreter (new accurate
  diagnostic).
- `2>&1 > file` remains order-insensitive (legacy).
- Leading `< in.txt cat` remains legacy's `<: command not found`.
- Non-last stdout redirection is ignored.
- `NIFT_FS_ROOT` does not constrain external child redirection.
- On Windows, `cmd &` keeps the pre-CP20 refusal (no Host job control).
- Interactive foreground/background job identities are both legacy (no mixed
  id spaces); scripts use Host.
