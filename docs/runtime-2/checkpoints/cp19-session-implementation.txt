CP19 persistent compiler/session implementation — development record
Foundation: CP18 8e65196b7f67abef317e7cfecb1eb97c227c5d96
Status: local development; not checkpoint acceptance or integration.

Authority and scope
One VM owns the session from construction (D-054). Unsupported compilation
refuses before effects without losing the session, selecting legacy, replaying
history, or copying executable state into Parser values. CP21 job control,
history and completion remain with their existing owner. CP24 stays deferred.
CP17 persistent resource admission awaits the exact owner-relayed integrated
interfaces. No replacement handle APIs, detach, or cleanup suppression exists.

Authoritative namespace and publication
VmSession owns stable cells and type slots; the shared compiler compiles each
new unit against immutable bounds. Compilation uses a private context, resolves
and checks the entire unit, and allocates publication containers before entry.
Refusal cannot update cells, consume callable identities or replace code.
Runtime failure preserves effects that executed and publishes only reached
bindings. Unreached slots stay reserved but invisible; later compatible
initialization preserves their original shape and mutability contract.

Callable ownership and specialization
Function values retain their Program independently of the VM. Immutable source
buffers and per-Proto maps retain definition origins across units. Weak code-unit
records reclaim unused slots; escaped function Values keep old code alive.
Equivalent specializations activate once at admitted unit entry, preserving
Function identity and captured cells. Ordinary call entry still follows the
Function's code pointer directly. Native array traversal and VM callback frames
remain the CP14B architecture, without a reentrant VM call or per-element codec.

Callable metadata describes actual reachable functions in objects, arrays and
plain captured cells. It stores identities, immutable definitions and structural
facts, never runtime Values or Program owners. Depth truncation, unsupported
locations and graph back edges are explicitly incomplete facts. Metadata
collection never resolves a selector. Callable facts overlay the compiler's
original structural bounds; observed values cannot narrow those bounds.
Plain-data aggregates use the existing identity summary and need no deep scan.
Immutable sanitized type graphs are shared across commands. Double-binding and aggregate-element numeric bounds are widened before initial
inference/compilation, not after publication. Int binding bounds remain integral.
Nested mutation effects, including loop-location aliases and captured arrays,
are compared with original structural bounds before execution. Session aggregate
loop bindings use the existing selector-cell path, avoiding an unmaterialised
lazy register. D-040 copies remain independent of the mutated source. Const
receiver checks retain their runtime error and preceding effects.
The runtime int/double binding checks still decide whether an assignment is
valid; a compiled type error retains any preceding explicit output/effects.

Only needed declarations are imported into fresh compilation; executable
statements are never replayed. Lambda wrappers seed capture bounds and are never
executed. Referencing a lambda template cannot install the caller's lexical
scope. Actual template traversal restores its original capture environment.
Named redefinition preserves the registry Function identity seen by aliases.
A mutable lambda binding can be rebound to a proven new lambda through its same
cell. Existing Function aliases retain the old identity; retained readers see
the cell's new value. Refusal consumes no callable identity and changes no code
owner; a runtime failure retains an executed rebind. Named/mixed-signature
rebinding and unproved textual arrow-assignment spellings remain refused.
Retained readers, including captured functions and object fields, are compiled
against a replacement before it can be admitted. Replacement takes effect at
its registration instruction. A mixed-order unit with executable statements
before an existing named replacement remains refused rather than observing
the replacement prematurely.

Named-reader admission checks parameters and local declarations that can shadow
an external free name. D-038 caller-dependent lookup is refused before effects;
unrelated lexical shadowing without a named free reader remains admitted.

Persistent structs
The existing CP12b subset now retains immutable schema declarations and stable
instance cells across units. Only already-admitted constant field initializers
and methods are imported; declaration-time executable statements are not replayed.
Type identities use schema names when a fresh compiler plan assigns local ids.
Methods receive an internal location number: ordinary scripts retain absolute
stack slots, while a session uses a checked encoding of a stable cell slot.
This adds no Frame field or borrowed register pointer. COW field updates reach
the same instance cell and preserve independent snapshots.

Schema publication follows successful whole-unit compilation. Refusal publishes
no schema; an admitted runtime failure retains schemas whose declarations
preceded executable statements under the existing CP12b ordering rule. Original
method source maps survive later construction/invocation. Reserved instance slots retain their original schema contract. Schema replacement,
name conflicts and unproved dynamic field shadowing refuse before effects.
Parameters/locals in a method with no call cannot expose a caller binding to a
second reader; ordinary constructor parameter names remain usable. Unrelated
callback parameters do not acquire a false struct dependency. Existing CP12b
struct sharing, alias, private-field and prepared-loop limits remain in force.
Capturing a local struct into a persistent closure is refused before effects;
the compiler cannot yet prove that field-access path.

Shell routes and presentation
.niftrc, interactive statements, file/stdin/inline -i continuation and selected
command interpolation share the same VM session. cmd and args are immutable
invocation cells. Classification does not execute or publish; shell syntax is
validated before interpolation. An internal VM failure is terminal status 70,
including interpolation and command-style Nift invocation, so later command
segments cannot run against a closed session.

The shared parser/compiler lower assignment expressions once. Indexed RHS and
target effects are not replayed. CP12 prepared-loop and index-target admission
rules remain in force. Quoted callbacks are parsed only for proven Array
receivers; ordinary string contents cannot import executable definitions.
Legacy's reserved method precedence is preserved using source-generated method
heads, rather than calling a same-named plain-object Function field.

REPL inspection and compound statement presentation are different legacy modes.
SessionRender buffers compound expression text; explicit print remains a real
side effect. Runtime failure discards buffered presentation, preserving explicit
output and cell effects. Prepared loop bodies and compiled push statements
retain their existing discard rules. .niftrc discards presentation, not print.
Caught Error payloads, identity, origin and handler selection remain unchanged;
Frame and Fault layout are unchanged.

API safety
Same-session reentry refuses before touching compilation or execution state.
Close requested from a flush callback is deferred until execution returns.
Per-command teardown clears temporary registers, frames, handlers and stale
named-function caches. Session namespace storage is charged to the configured
heap budget. Fatal internal stops close the session; runtime Errors retain it.

Remaining admission boundaries
The compiler's established unsupported syntax, builtins, alias/handle and
prepared-context refusals remain. CP19 additionally refuses widening an older
binding/capture contract, unsupported callable rebinding, unproved callable
flow, mixed-order named replacement, dynamic named-function shadowing and
unproved struct capture/schema replacement. These are coverage limitations, not execution
passes, compatibility waivers or justification to switch a VM session engine.
The final traceability/refusal inventory must identify their release impact.

Evidence policy
Affirmative VM and zero legacy counts are required for admitted cases in both
dispatches. Refusals are counted separately. Runtime failures must retain effects
without replay. Exact parity, compiled behavioral mutants, ownership/source-map
checks and ASan/LSan/UBSan support local verification. An implementation owner's
rerun of reviewer tests is not independent acceptance. Original evidence is
preserved; later fixes get new logs. Final performance, resource reconciliation
and macOS/Windows certification are not implied by local functional passes.
