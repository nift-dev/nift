# CP20 R1 corrections

**Base:** CP20 candidate `5dedd9be` (tree `47738625`, on `e1f2f59f`).
**Correction commits:** `a6bbbad8`, `73b05553` (new commits, provenance kept).

## Execution contexts (J1)

| Context | Launcher / job table |
|---|---|
| Interactive terminal, foreground simple command or pipeline | **Legacy** `ShellJobTable` and legacy launcher: process group, terminal hand-off, Ctrl-C/Ctrl-Z, `Stopped`, `fg`/`bg`, `jobs` |
| Interactive terminal, background `&` | **Legacy** `ShellJobTable` (R2 J1 extension): one id space with foreground jobs, `fg`/`wait`/`jobs` consistent; no terminal hand-off |
| Scripted / non-interactive, foreground and background | Host `ProcessGroup` |
| Windows | Existing legacy launcher; CP20W is a separate checkpoint and was not started |

This preserves the complete interactive foreground and background job-control
path until CP21 adds Host stop/continue. Scripts have no job-control contract
and use Host. R2 supersedes the R1 interactive-background mix.

## Corrections

- **D1** Ctrl-C no longer kills the shell: interactive foreground is the legacy
  job-control path. `tests/cp20_r1.py` checks the shell survives, the next
  command runs, and `jobs` records `Done (130)`.
- **D2** Ctrl-Z: the legacy foreground path prints `[1] Stopped`; `fg` resumes.
  PTY-tested in `cp20_r1.py` (and 20/20 in `test-cp20-r1-flake`).
- **D3/H1** `cmd &` uses Host with `TerminalPolicy::Never`; the shell keeps the
  terminal and `wait` reaps the group. `SpawnRequest::terminal` and the
  hand-off site in `process_posix_launch.cpp` are the only Host-option changes.
  `terminal_never_option` is a `test-rt-host` case.
- **D4** FD limits restored: a 3-stage pipeline at `ulimit -n 8` and 8 stages at
  `-n 10` succeed. `exec_report_optional` is enabled for the shell's Host
  launches, preserving the CP07 low-fd contract; no descriptors leak in the
  PTY before/after check.
- **D5** Missing-shebang diagnostics name the interpreter
  (`interpreter not found: /no/such/interpreter (from …)`). Intentional legacy
  differences are listed in the R1 report: richer stdin/stdout open errors and
  `2>&1 |` acceptance (the latter is required by CP20). `2>&1 > file` remains
  legacy order-insensitive; leading redirection remains legacy's
  `<: command not found`.
- **D6** Each mutant is rejected by the ordinary CP20 suite. The harness checks
  the named failing fixture; M5 now leaves a background job un-waited and is
  caught by `background-leftover`.
- **D7** New tests: real PTY SIGINT/Ctrl-Z/background-terminal, fd limits and
  descriptor leak, leftover jobs, `NIFT_FS_ROOT` redirection, D5 messages and
  interpreter naming; all wired into `test-cp20-r1`.
- **D8** Windows fallback now calls
  `nift_run_pipeline(stages, !direct, !direct)`, restoring the legacy capture
  flags/CRLF normalisation. A Windows-only CRLF fixture is provided for CI;
  local execution is POSIX, so Windows CI is required.
- **pgid set** managed pgids are released when the `ProcessGroup` object is
  destroyed (not at stage exit, so subreaper orphan attribution remains valid).
  `managed_pgid_cleanup` starts and waits 10,000 groups and requires the set to
  return to zero.

## Performance (P2)

Interleaved 30 rounds × 200 launches, temporary `HOME`, external
`/usr/bin/true`, same compiler/flags. Local medians (ms/launch):

| Workload | bash | pre-CP20 | CP20 R1 | R1/pre |
|---|---:|---:|---:|---:|
| single | 0.6595 | 0.7660 | 0.7854 | **1.025** (≤1.03) |
| 3-stage | 0.8753 | 0.9568 | 1.5622 | **1.633** (fail) |

Certification Linode (`g6-dedicated-4`, GCC 13.3; instance `108888104`):

| Workload | bash | pre-CP20 | CP20 R1 | R1/pre |
|---|---:|---:|---:|---:|
| single | 0.8715 | 1.0035 | 1.0100 | **1.006** (pass) |
| 3-stage | 1.4197 | 1.4880 | 2.0198 | **1.357** (fail) |

Interactive PTY benchmark (legacy path) local: pre 0.7191, R1 0.7198 ms/launch
(ratio 1.001). The P2 gate is not met for 3-stage pipelines; this is reported,
not waived. `≤ bash + 10 %` is also missed and is not claimed as achieved.

## Limits

Windows Host execution remains CP20W (not started). The Windows CRLF fixture
skips on POSIX; Windows CI must run it. The local ASan/UBSan run excludes the
PTY-only tests on non-POSIX platforms.
